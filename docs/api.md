# HTTP API и вход

Все JSON-ответы имеют `Cache-Control: no-store`. Рабочий домен задаёт `PUBLIC_ORIGIN`. Node.js слушает loopback; внешние запросы поступают через Nginx.

| Метод и путь                | Назначение                                | Доступ                            |
| --------------------------- | ----------------------------------------- | --------------------------------- |
| `GET /api/health`           | Проверка процесса и базы                  | Всем                              |
| `GET /api/session`          | `canEdit` и признак локального режима     | Всем                              |
| `POST /api/login`           | Вход: JSON `username`, `password`         | Всем                              |
| `POST /api/logout`          | Завершение текущего сеанса                | Текущий сеанс                     |
| `GET /auth/yandex`          | Начало входа через Яндекс                 | Всем, если настроено              |
| `GET /auth/yandex/callback` | Проверка ответа Яндекса и создание сеанса | Проверяется одноразовое состояние |
| `POST /auth/logout`         | Выход из Древа                            | Текущий сеанс                     |
| `GET /api/family`           | `{ family, revision, canEdit, local }`    | По настройке видимости            |
| `PUT /api/family`           | Записать объект `Family`                  | После входа                       |
| `POST /api/photos`          | Загрузить бинарный файл                   | После входа                       |
| `GET /media/<имя>`          | Получить фотографию                       | По настройке видимости            |
| `GET /api/export`           | Скачать JSON семейных данных              | По настройке видимости            |
| `GET /api/backup`           | Скачать согласованную копию `.sqlite`     | После входа                       |

При `ARCHIVE_PRIVATE=1` семейные данные и фотографии доступны только после входа. При `0` просмотр открыт, редактирование и бэкап всё равно требуют входа. Без `PUBLIC_ORIGIN` используется доверенный локальный режим: вход не нужен, сервер доступен только на компьютере.

## Сохранение архива

```http
PUT /api/family
Content-Type: application/json
If-Match: 7

{"title":"Наша семья","description":"","demo":false,"people":[]}
```

Успех возвращает `{ family, revision }` с увеличенной версией. Версия берётся из последнего ответа сервера. `409` означает изменения в другой вкладке: сохраните свой текст отдельно, обновите страницу и внесите изменения в свежие данные. `428` — отсутствующая или некорректная версия, `400` — ошибка проверки, `401` — требуется вход, `413` — превышен размер, `415` — неверный тип содержимого.

## Загрузка фотографии

Тело `POST /api/photos` — байты JPEG, PNG, WebP или GIF до 20 МБ. Заголовки: `If-Match`, `X-Drevo-Upload: 1`, `X-File-Name` с именем в `encodeURIComponent`, соответствующий `Content-Type`. Ответ `201` содержит обновлённый архив. Сервер проверяет сигнатуру, сохраняет файл под случайным именем и создаёт запись без отметок. Отметки сохраняются обычным `PUT /api/family`.

## Авторизация

На сервере есть учётная запись редактора с паролем и необязательный вход через Яндекс для разрешённых ID. Пароль хранится в виде scrypt-хеша с индивидуальной солью, заданного через `ARCHIVE_PASSWORD_HASH`. `ARCHIVE_USER` задаёт логин. Исходный пароль в базу и Git не записывается. Подключение провайдера описано в [документации OAuth](yandex-oauth.md).

При входе устанавливается cookie `drevo_session`: `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS, срок 12 часов. Сеансы находятся в памяти процесса; после перезапуска или деплоя нужно войти снова. После 10 неудачных входов с одного адреса действует задержка до 15 минут. Nginx заменяет `X-Real-IP` адресом клиента.

Изменяющие запросы проверяют Origin и `Sec-Fetch-Site`. Нельзя размещать приложение в интернете без `PUBLIC_ORIGIN` и настроенного хеша пароля: локальный режим предназначен для доверенного компьютера.
