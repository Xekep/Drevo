# HTTP API

JSON-ответы имеют `Cache-Control: no-store`. Авторизация — через [Яндекс OAuth](yandex-oauth.md). На компьютере без `PUBLIC_ORIGIN` действует локальный доступ администратора без регистрации.

При настроенном SMTP и PostgreSQL доступны `POST /api/auth/email/register` (`email`, `name`, `password`), `/verify` (`token`), `/login` (`email`, `password`), `/reset/request` (`email`) и `/reset/complete` (`token`, `password`). Письма содержат одноразовые ссылки с токеном во фрагменте URL; вход и подтверждение устанавливают тот же сеансовый cookie, что OAuth. `GET /api/session` возвращает `email: true` только когда почтовый вход реально настроен. Запросы требуют JSON и того же origin; неизвестные адреса при регистрации и запросе восстановления получают общий ответ.

Вошедший через Яндекс или VK пользователь может подключить почту без второго дерева: `POST /api/auth/email/link/request` (`email`, `password`) отправляет письмо, а `POST /api/auth/email/link/verify` (`token`) подтверждает. Оба запроса требуют свежего OAuth-входа в исходный аккаунт; совпадение адреса не объединяет аккаунты.

### Потоковый ИИ-чат

`POST /api/ai/chat/stream` принимает то же тело, что и `POST /api/ai/chat`, но возвращает `text/event-stream` с событиями `status`, `delta`, `done` и `error`. `done` содержит итоговый текст и проверенные `references`.

### Администрирование AI Studio

- `GET /api/admin/ai` — состояние конфигурации, эффективная модель, лимиты, дневная статистика и последние технические записи без серверных секретов.
- `PUT /api/admin/ai` — включение/выключение ИИ и переопределение модели.
- `POST /api/admin/ai/models` — получить через сервер доступные Folder ID модели, используя введённый или уже сохранённый API-ключ.
- `POST /api/admin/ai/test` — проверка подключения к текущей модели.

API-ключ и Folder ID не возвращаются клиенту; UI получает только признаки их наличия.

### MCP audit

`GET /api/mcp/tokens` возвращает список токенов с их rate limit и дневной технической статистикой, а также `recentUsage` без аргументов вызовов. При превышении лимита `POST /mcp` отвечает HTTP 429 и `Retry-After`.

## Снимок и права

Для интерфейса также предусмотрены запросы:

- `GET /api/family?projection=overview`: облегчённый `family`, `partial:true`, `pageToken`, `totals:{people,photos}`. Весь граф, имена, даты и места доступны сразу; биографии, занятия, награды, источники и галерея загружаются следом.
- `GET /api/family?projection=page&collection=people|photos&offset=0&token=<pageToken>`: `{pageToken,total,items}`, до 40 записей. Для людей — только `{id,sources,biography?,occupation?,awards?}`, для снимков — полные доступные метаданные. Следующее смещение увеличивается на число полученных записей. Изменение ревизии или видимости даёт `409`; токен не заменяет сессию. До завершения всех страниц редактирование отключено. [Границы загрузки](loading.md).
- `GET /api/people/search?q=...`: `{people:[{id,label,detail}],hasMore}`, до 20 результатов. От 2 до 100 символов, поиск по ФИО, фамилии при рождении и годам, с учётом `е/ё`. Доступ под сессией либо при публичном древе. Публичные альбомы не открывают поиск закрытых людей.
- `POST /api/portraits`: изображение до 20 МБ, `If-Match`, `X-Drevo-Upload:1`. Только администратор или родственник. Ответ `201 {url}`; файл сохраняется отдельно, галерея и ревизия не меняются. Портрет назначается через обычный `PUT /api/family` с проверкой авторства.
- `GET /media/<файл>?variant=thumb|display`: WebP до 400/1600 px, без параметра — оригинал. Права одинаковы для всех вариантов. При ошибке преобразования возвращается оригинал с его Content-Type. [Качество и хранение](photo-assistant.md).

`GET /api/family` возвращает `{family, revision, user, canEdit, local, readTree, readPhotos, reverseTimeline}`. У незарегистрированного посетителя закрытые разделы исключаются из ответа. Если открыты только альбомы, отсутствуют люди, связи и персональные отметки. Если открыто только древо, отсутствуют фотографии и портреты. Если оба раздела закрыты, возвращается `401`.

Вошедший читатель видит весь архив, но не может его изменять. Скрытые кнопки дополняются серверной проверкой каждого изменённого объекта. Клиент не может подменить автора через `createdBy`.

## JSON для анализа

**`GET /api/export.json`** — читаемая выгрузка без фото. На рабочем сайте: <https://mydrevo.org/api/export.json>. Параметр `?download=1` скачивает файл `drevo-family.json`; без параметра сервер возвращает JSON для прямого чтения.

Доступ разрешён, если `publicTree=true` **или** есть действующая сессия любой роли. Публичные альбомы при закрытом древе не дают доступа к выгрузке. Без входа в закрытый архив — `401`; методы кроме GET — `405`. Ответ не кэшируется (`Cache-Control: no-store`). Ссылка не содержит секретов и не обходит вход: для анализа закрытого архива скачайте JSON в своём браузере и передайте файл нейронке.

Корневые поля: `format: "drevo.genealogy"`, `version: 1`, `exportedAt` (UTC), `revision`, `title`, `description`, `semantics`, `people`, `links`. `semantics` поясняет направления связей, неизвестные даты и словарь дополнительных ролей. `people` содержит исходные идентификаторы, ФИО, пол, даты и места рождения/смерти, уточнённые координаты при наличии, девичью фамилию, занятия, биографию, `parents`, `parentageComplete`, `spouses` и `sources`. `links` содержит `id`, `from`, `to`, `type`, `note`: например, `from` — крёстный родитель человека `to` при `type: "godparent"`.

Нет фото карточек, альбомов, отметок, путей к загруженным фото, авторов записей, аккаунтов или координат раскладки. Ссылки на источники сохраняются. Визуальные повторы человека в нескольких союзах не дублируют его в JSON. Отсутствующие данные не достраиваются; порядок супругов не означает очередность браков. Этот формат предназначен для анализа, а не для импорта или полного восстановления архива.

Поле `people[].awards`, если есть, содержит награды `{id, name, year?, source?: {title, url?}}`. Значки наград и декоративный голубь — элементы интерфейса, изображений в JSON нет.

## Сохранение

`GET /api/places/locate?q=...` с `X-Drevo-Map: 1` возвращает `{query,candidates,automatic?,notice?}`. `notice` сообщает о временно недоступной части поиска, не блокируя доступные варианты и ручной выбор точки. Endpoint доступен при доступе к древу или альбомам; читатель может искать только места из доступных карточек и снимков, редактор — также уточняющие названия. Запросы проверяют Origin, полные ответы кэшируются на сервере. [Подробности карты](places.md).

`POST /api/restore/preview` с `X-Drevo-Restore: 1` принимает бинарный бэкап до 12 ГиБ и возвращает состав, количество отсутствующих фото, текущую ревизию и временный `token`. SQLite внутри архива ограничена 512 МиБ. `POST /api/restore/apply` принимает JSON `{token,confirm:true}`. Оба endpoint доступны только администратору; применение проверяет владельца токена, срок 15 минут и отсутствие изменений архива после проверки. [Что именно восстанавливается](backup.md).

`GET /api/drevo/export` отдаёт владельцу выбранного дерева потоковый `.drevo` с манифестом и SHA-256 оригиналов. Это экспорт для хранения; обратный импорт ещё не доступен. [Состав и ограничения пакета](portable-format.md).

`PUT /api/family` принимает JSON `Family` до 8 МБ. Заголовок `If-Match` обязателен и содержит `revision` последнего снимка. Ответ `{family,revision}` содержит сохранённые сведения и увеличенную версию. При `409` клиент получает свежий снимок и сверяет его с исходным состоянием и черновиком. Независимые поля объединяются, для совпавших пользователь выбирает вариант. Повторный `PUT` содержит проверенный объединённый граф и свежую версию. Смена типа или участников связи сохраняется одним запросом; отмена использует тот же API и те же проверки прав.

Для человека неизвестная дата рождения передаётся как `birth: ""`, неизвестный пол — как `sex: "u"`. Допустимы также `sex: "m"` и `sex: "f"`. Фамилия и имя обязательны; форма сама формирует полный объект с пустыми необязательными сведениями, массивами связей и служебными полями. API по-прежнему принимает полный снимок, а не только строку ФИО. Ранее сохранённые записи с датами и полом продолжают работать без преобразования.

`POST /api/photos`: тело — JPEG/PNG/WebP/GIF до 20 МБ; заголовки `If-Match`, `X-Drevo-Upload: 1`. Сервер назначает случайное имя, автора и `createdAt` в UTC. Название не требуется и не берётся из имени файла. Предложения модели лиц остаются в браузере до ручного подтверждения; подтверждённые отметки сохраняются обычным `PUT /api/family`.

`POST /api/faces/match` принимает JSON `{descriptor}` с одним 128-мерным вектором и возвращает `{match:null}` либо `{match:{personId,distance}}`. Временный вектор используется только для сравнения, не записывается в базу и не возвращает клиенту сохранённые отпечатки. `POST /api/faces/descriptors` принимает `{id,personId,descriptor}` только после подтверждения отметки. Оба запроса доступны редакторам, ограничены по размеру и проверяют источник; `GET /api/faces/descriptors` намеренно не поддерживается.

Коды: `400` — некорректные данные, `401` — требуется вход, `403` — недостаточно прав, `409` — конфликт версии, `413` — превышен размер, `415` — неверный Content-Type, `428` — отсутствует версия. Изменяющие запросы проверяют Origin и `Sec-Fetch-Site`.

При загрузке фото необязательный `X-Photo-Metadata` содержит JSON `{year, place, event, description}`, закодированный через `encodeURIComponent`. Поле `title` принимается для совместимости, но интерфейс его не показывает. Метаданные сохраняются вместе с фотографией в одной записи архива; неподходящие значения отклоняются, созданный файл убирается при ошибке. Автор и путь назначаются сервером.

`reverseTimeline: true` располагает младшие поколения выше старших. Изменять это поле может только администратор. Старые запросы видимости без `reverseTimeline` сохраняют текущее направление шкалы.

## Управление резервными копиями

Все `/api/backups*` доступны только одобренному администратору. Ответы не кешируются. Изменяющие запросы требуют same-origin и заголовок `X-Drevo-Backup: 1`.

| Запрос | Назначение |
| --- | --- |
| `GET /api/backups?offset=0` | Настройки, следующий запуск, текущее/последнее задание и 20 копий из каталога |
| `PUT /api/backups/settings` | `{enabled, intervalHours, keepCount, storage, remoteHost, remoteDirectory}`; период 1–720 часов, количество 1–365, хранилище `local`/`remote` |
| `POST /api/backups/create` | Фоновое создание по сохранённым настройкам, `202` и ID задания |
| `POST /api/backups/check` | Проверка SSH-подключения и прав записи; тело как settings, `202` |
| `GET /api/backups/:id/download` | Проверить SHA-256 и скачать выбранную полную копию |
| `POST /api/backups/:id/preview` | Фоновая проверка выбранной копии, `202`; по завершении автор получает preview/token в статусе |

Второе параллельное задание отклоняется с `409`. Перезапуск не теряет расписание и не снимает блокировку до истечения аренды. Токен предварительного просмотра доступен только администратору, который его запросил. Применение — существующий `POST /api/restore/apply` с `X-Drevo-Restore: 1` и `{token, confirm: true}`. Проверка устаревшей revision возвращает `409`. Сохранение настроек не запускает немедленное удаление старых копий; ротация выполняется после успешной следующей копии.

`remoteHost` — имя серверного SSH-профиля, а не пароль или произвольная команда. Приватный ключ и закреплённый host key настраиваются на сервере вне браузера. [Инструкция](backup.md).

## ИИ-исследователь и MCP

`GET /api/ai/status` возвращает состояние ИИ для вошедшего участника. `POST /api/ai/chat` и потоковый `POST /api/ai/chat/stream` принимают `{message,chatId?,context?}` и возвращают `chatId`; клиентская история в prompt больше не принимается. `GET /api/ai/chats` возвращает список своих чатов, `GET /api/ai/chats/:id` — сообщения, `DELETE /api/ai/chats/:id` удаляет локальный чат и best-effort remote conversation. Сервер вызывает разрешённые Research Tools через Yandex Responses API. API-ключ остаётся на сервере; участник с `common_ancestors` анализирует ту же ограниченную проекцию, что видна в интерфейсе. Изменения доступны только редактору и создаются как предложения, применяемые отдельной кнопкой подтверждения.

Администратор управляет внешним доступом через `GET/POST /api/mcp/tokens` и `DELETE /api/mcp/tokens/<id>`. При создании полный секрет возвращается один раз; в базе остаются SHA-256, короткая подсказка, scopes, срок и служебные даты.

MCP доступен по `/mcp` с `Authorization: Bearer drevo_mcp_...`. Инструменты только читают данные. Scopes разделяют сведения древа и фото (`tree:read`), источники (`sources:read`) и вычисляемую аналитику (`analysis:read`). Отпечатки лиц, аккаунты и административные настройки через Research Tools не выдаются.

Подробнее: [ИИ-исследователь и MCP](ai-research.md), [дорожная карта](roadmap.md).

### MCP user binding

При выдаче токена `POST /api/mcp/tokens` можно передать `boundUserId`. `GET /api/mcp/tokens` возвращает `bindings` — одобренных участников, которых можно использовать для привязки. Привязанный токен наследует `personId` и `treeAccess` участника; для `common_ancestors` все Research Tools работают с той же ограниченной проекцией, что и веб-интерфейс.
