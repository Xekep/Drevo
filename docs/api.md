# HTTP API

JSON-ответы имеют `Cache-Control: no-store`. Авторизация — через [Яндекс OAuth](yandex-oauth.md). На компьютере без `PUBLIC_ORIGIN` действует локальный доступ администратора без регистрации.

| Метод и путь                | Назначение                                           | Доступ                                                      |
| --------------------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| `GET /api/health`           | Проверка процесса и базы                             | Всем                                                        |
| `GET /api/session`          | Текущий `user`, роль, `canEdit`, доступность Яндекса | Всем                                                        |
| `GET /auth/yandex`          | Начало входа                                         | Всем                                                        |
| `GET /auth/yandex/callback` | Проверка ответа провайдера                           | Одноразовое состояние браузера                              |
| `POST /auth/logout`         | Выход                                                | Текущий сеанс                                               |
| `GET /api/family`           | Снимок данных и версия                               | По настройкам публичности                                   |
| `PUT /api/family`           | Сохранение семейного архива                          | Администратор; родственник только в пределах своих объектов |
| `POST /api/photos`          | Загрузка бинарной фотографии                         | Администратор или родственник                               |

## Снимок и права

`GET /api/family` возвращает `{family, revision, user, canEdit, local, readTree, readPhotos}`. У незарегистрированного посетителя закрытые разделы исключаются из ответа. Если открыты только альбомы, отсутствуют люди, связи и персональные отметки. Если открыто только древо, отсутствуют фотографии и портреты. Если оба раздела закрыты, возвращается `401`.

Вошедший читатель видит весь архив, но не может его изменять. Скрытые кнопки дополняются серверной проверкой каждого изменённого объекта. Клиент не может подменить автора через `createdBy`.

## Сохранение

`PUT /api/family` принимает JSON `Family` до 8 МБ. Заголовок `If-Match` обязателен и содержит `revision` последнего снимка. Ответ `{family,revision}` содержит сохранённые сведения и увеличенную версию. При `409` другая вкладка изменила архив: сохраните текст отдельно, загрузите свежий снимок и повторите правку.

`POST /api/photos`: тело — JPEG/PNG/WebP/GIF до 20 МБ; заголовки `If-Match`, `X-Drevo-Upload: 1`, `X-File-Name` в `encodeURIComponent`. Сервер назначает случайное имя и автора. Предложения модели лиц остаются в браузере до ручного подтверждения; подтверждённые отметки сохраняются обычным `PUT /api/family`.

Коды: `400` — некорректные данные, `401` — требуется вход, `403` — недостаточно прав, `409` — конфликт версии, `413` — превышен размер, `415` — неверный Content-Type, `428` — отсутствует версия. Изменяющие запросы проверяют Origin и `Sec-Fetch-Site`.
