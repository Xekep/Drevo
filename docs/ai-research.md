# ИИ-исследователь и MCP

Drevo использует единый read-only слой исследовательских инструментов. Его вызывают встроенный веб-ассистент и внешний MCP endpoint. Это не даёт модели прямого доступа к SQLite и не дублирует генеалогическую логику в промптах.

## Веб-ИИ

Серверный маршрут POST /api/ai/chat обращается к OpenAI-совместимому Chat Completions API Yandex AI Studio. API-ключ хранится только в окружении сервера.

Переменные окружения:

    YANDEX_AI_API_KEY=...
    YANDEX_AI_FOLDER_ID=<folder-id>
    YANDEX_AI_MODEL=yandexgpt/rc
    YANDEX_AI_BASE_URL=https://ai.api.cloud.yandex.net/v1

`YANDEX_AI_MODEL` можно задать полным `gpt://` URI; иначе сервер формирует URI из `YANDEX_AI_FOLDER_ID`. `YANDEX_AI_MODEL` по умолчанию — `yandexgpt/rc`, `YANDEX_AI_BASE_URL` необязателен.

ИИ доступен только вошедшему участнику с правом чтения закрытого архива. Для участника с ограничением common_ancestors Research Tools получают ту же серверную проекцию, что и остальные способы чтения древа.

Первый вариант не отправляет модели фотографии, пути к медиа, createdBy, face descriptors, пользователей и настройки доступа.

## MCP

Endpoint:

    https://<host>/mcp

Авторизация:

    Authorization: Bearer drevo_mcp_...

Токен создаётся администратором в разделе «Управление → MCP и ИИ». Полный секрет возвращается только при создании; в SQLite хранится SHA-256 и короткая подсказка.

Scopes:

- tree:read — поиск людей, карточки, семья, предки и потомки;
- sources:read — источники;
- analysis:read — родство, пробелы, противоречия и сводная аналитика.

MCP работает stateless поверх JSON-RPC. Для MCP 2026-07-28 поддержан `server/discover` и прямые `tools/list` / `tools/call`; для клиентов 2025-era сохранён `initialize` и `notifications/*`. Дополнительная runtime-зависимость от MCP SDK для первого read-only слоя не требуется.

Встроенный ассистент умеет запускать детерминированный `get_branch_insights`: выбранный человек, направление ветки и глубина задаются отдельно, а Drevo сам считает полноту, пробелы и предупреждения до передачи результата модели.

Все опубликованные MCP tools на первом этапе read-only.

## Граница доверия

Языковая модель объясняет и сопоставляет сведения, но вычисляемые проверки выполняет Drevo. Если модель предлагает новый факт, это пока остаётся текстовой гипотезой. Планируемая запись в архив будет реализована через отдельные propose_* операции с ручным подтверждением, а не через автономный полный снимок семейного графа.


## Предложения изменений

Пользователь с правом редактирования может попросить ИИ сохранить конкретное уточнение как предложение. Для карточки человека доступен tool `propose_person_update`.

Предложение хранится отдельно от семейного графа и содержит исходные значения полей, новые значения, основание, дополнительные свидетельства и ревизию архива. В панели ИИ оно показывается как «было → станет» с кнопками **«Принять»** и **«Отклонить»**.

До подтверждения семейный архив не меняется. При принятии сервер повторно проверяет права и доменную валидацию. Если затронутое поле изменилось после создания предложения, применение останавливается конфликтом вместо тихой перезаписи новых данных.

Поддерживаются три типа предложений: безопасные поля карточки человека, новый источник карточки и новая связь между существующими людьми. Для связи `parent` направление явно задано как «from = родитель, to = ребёнок»; супружество симметрично, дополнительные роли используют те же направления, что и обычная модель Drevo.

Источник и связь тоже не меняют архив до ручного подтверждения. Перед применением Drevo проверяет, что соответствующие источники или связи не изменились после создания предложения, а затем пропускает результат через обычные права и `validateFamily`.


## Исследовательский backlog

`get_research_backlog` строит план следующего поиска без участия языковой модели в ранжировании. Tool может работать по всему архиву или по выбранной ветке и глубине.

Для каждого человека Drevo формирует кандидаты документов: запись о рождении/крещении, запись о браке, запись о смерти/погребении и перепись/посемейный список/домовую книгу. Приоритет учитывает, какие пробелы документ способен закрыть, есть ли уже поисковые ориентиры по году и месту и насколько человек близок к выбранному узлу ветки.

Результат содержит причину приоритета, ожидаемые поля и известные ориентиры для поиска. Тип документа остаётся обобщённым: конкретный архивный фонд или учреждение зависит от страны, периода и административной истории и не придумывается Drevo без источника.


## Вероятные дубли

`find_possible_duplicates` отделён от `find_inconsistencies`: возможный дубль является гипотезой, а не ошибкой архива.

Сначала Drevo сужает число пар по нормализованному имени, затем выставляет балл по совокупности признаков. Учитываются кириллическое/латинское написание фамилии, небольшие опечатки, фамилия при рождении, отчество, известный год рождения и смерти, частично совпадающие места, общие родители и супруги. Неизвестный год не считается конфликтом, а заметно разные известные годы снижают балл.

Tool возвращает только пары выше порога и объясняет, какие признаки повысили оценку и какие известные данные ей противоречат. Даже высокий балл остаётся кандидатом для ручной проверки и не приводит к автоматическому объединению карточек.


## Ссылки из ответа

Веб-ИИ возвращает вместе с текстом структурированный список `references`. Список строится сервером из результатов реально выполненных tool-calls, а не извлекается моделью из собственного текста.

Для человека reference содержит стабильный `personId` и отображаемое имя. Нажатие на chip в ответе открывает соответствующую карточку в Drevo. Для источника reference содержит владельца карточки, название, архивную ссылку и безопасный HTTP/HTTPS URL, если он был записан в источнике. Источник с URL открывается напрямую; источник без URL ведёт к карточке человека, где хранится запись.

Сервер ограничивает число возвращаемых references и не включает фотографии, face descriptors, аккаунты или служебные поля.


## Настройка AI Studio в админке

В разделе **«MCP и ИИ»** администратор видит состояние серверной конфигурации AI Studio без раскрытия секретов. Интерфейс показывает, заданы ли API-ключ и Folder ID, эффективную модель и endpoint.

Можно временно выключить встроенного ИИ-исследователя без удаления конфигурации и сменить модель. Пустое поле модели возвращает управление переменной `YANDEX_AI_MODEL` или значению по умолчанию `yandexgpt/rc`. Изменения применяются к следующим запросам без перезапуска Drevo и записываются в аудит.

Кнопка **«Проверить подключение»** выполняет минимальный серверный запрос к текущей модели. API-ключ никогда не возвращается в браузер и не хранится в SQLite.


## Лимиты и наблюдаемость

Администратор задаёт три независимых ограничения: число запросов в минуту на пользователя, число запросов в день на весь архив и число токенов в день на весь архив. Значение `0` отключает соответствующий лимит. При превышении минутного лимита `/api/ai/chat` отвечает HTTP 429 и, когда возможно, заголовком `Retry-After`; запрос в AI Studio при этом не выполняется.

Одна пользовательская реплика считается одним запросом Drevo. Если для неё модель делает несколько function-calling раундов, они отражаются отдельно как `providerCalls`. Токены берутся из поля usage ответа AI Studio, а если провайдер его не прислал, Drevo сохраняет грубую оценку по объёму JSON. Поэтому этот счётчик подходит для ограничения и наблюдаемости, но не является биллинговым документом.

В админке показываются дневные запросы, provider calls, input/output/total tokens, ошибки, средняя задержка и последние технические записи. Таблица `ai_usage` не хранит тексты сообщений, ответы модели или аргументы Research Tools.


## MCP: аудит и rate limit

Каждый MCP-токен имеет собственный лимит запросов в минуту. По умолчанию это 60 запросов/мин; `0` отключает ограничение. При превышении endpoint отвечает HTTP 429 с `Retry-After`, не выполняя Research Tool.

Для валидных RPC-вызовов Drevo хранит технический журнал `mcp_usage`: токен, RPC-метод, имя инструмента для `tools/call`, результат и задержку. Параметры JSON-RPC, аргументы Research Tools, поисковые строки и идентификаторы из arguments не сохраняются.

Администратор видит дневное число вызовов, ошибок, среднюю задержку по токену и последние технические записи в разделе **«MCP и ИИ»**.
