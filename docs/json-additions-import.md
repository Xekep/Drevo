# Пакетное добавление карточек из JSON

Администратор архива открывает **Импорт** правой кнопкой на пустом месте древа,
рядом с экспортом. На телефоне импорт и экспорт скрыты с полотна древа.
Тот же блок находится в управлении архивом, в разделе переноса данных.

1. Выберите пакет JSON и нажмите **Проверить пакет JSON**.
2. Просмотрите количество людей и связей, список новых карточек, отдельные ветки
   и предупреждения о возможных дублях. При ошибках добавление заблокировано.
3. Нажмите **Добавить … карточек**. Все записи сохраняются одной транзакцией.

Импорт создаёт только новые карточки и дополнительные связи между новыми людьми.
Существующие люди, их поля, отметки проверки, фотографии, документы и настройки
не изменяются. Новые карточки всегда получают `needsReview: true` и автора,
определённого сервером. Источники, даты смерти и события сохраняются.

Лимиты: 1000 новых людей, 3000 дополнительных связей, 8 МБ на HTTP-запрос.
Новые супруги должны ссылаться друг на друга. Родитель новой карточки может быть
уже существующим человеком. Чтобы добавить предка существующему человеку,
потребуется отдельно изменить его карточку: пакет этого не делает. Предпросмотр
показывает число новых людей, которые останутся отдельными ветками.

## Формат

```json
{
  "format": "drevo.reviewed-add-only",
  "version": 1,
  "existingPeople": [],
  "newPeople": [
    {
      "id": "example-new-person",
      "surname": "Примеров",
      "name": "Иван",
      "patronymic": "Петрович",
      "sex": "m",
      "birth": "1900",
      "death": "1970",
      "parents": [],
      "spouses": [],
      "sources": [
        {
          "title": "Семейная запись",
          "type": "Документ",
          "reference": "Лист 1"
        }
      ]
    }
  ],
  "newLinks": []
}
```

У карточек и дополнительных связей должны быть стабильные уникальные `id`.
Если ID уже существует, весь пакет отклоняется: автоматического объединения,
перезаписи и повторного создания нет. Возможные совпадения ФИО и года рождения
показываются отдельно, поскольку это не доказательство тождества людей.
Пакеты с непустым `existingPeople`, неизвестными полями карточек, авторством или
медиа не принимаются. Полный JSON-экспорт и `add-only-request.json` со списком
API-изменений не являются пакетами этого формата.

`generation` и `column` из подготовленных пакетов принимаются для совместимости,
но получают начальные значения обычного импорта Drevo; геометрию рассчитывает
существующий layout. Служебные поля пакета `status`, `baseExportRevision`,
`baseExportSha256`, `sourceFile`, `applicationNote`, `omittedExistingConnection`
не считаются инструкциями, не меняют данные и не задают текущую ревизию.

## Проверки и ограничения

Используются `validatedChanges` / `validateFamily` и `analyzeArchiveWarnings`:
ссылки, циклы, даты, несовместимые роли, необычный возраст родителей и рождение
более чем через 300 дней после последней возможной даты смерти родителя.
Дополнительно блокируются рождение после смерти матери, непересекающиеся периоды
жизни супругов и брак после смерти самого человека. Смерть супруга относительно
брака проверяется при единственном указанном супруге: события Drevo пока не
содержат ID участника брака, поэтому при нескольких браках автоматически выбирать
супруга нельзя. Год и месяц рассматриваются как интервалы дат; посмертное рождение
у отца не отвергается автоматически.

Неполные сведения допустимы. Проверка JSON не заменяет чтение первичных документов
и не может обнаружить противоречащую дату, которую заранее удалили из файла.
Нельзя исправлять конфликт простым удалением даты: такие записи сначала нужно
исключить из пакета вместе с зависимыми связями.

## Сохранение и API

`POST /api/import/additions/preview` принимает `{ "package": ... }` и возвращает
предпросмотр, актуальную `revision` и `fingerprint`. Отпечаток связывает нормализованные
добавления с архивом, администратором и ревизией; это контроль целостности, а не
токен авторизации. Предпросмотр не меняет базу и не передаёт файл провайдеру ИИ.

`POST /api/import/additions/apply` принимает тот же пакет, `revision`, `fingerprint`
и `confirm: true`. Сервер повторяет проверки, формирует только операции создания
через доменную модель и вызывает существующий `archive.write`. Транзакция проверяет
ревизию и права, сохраняет историю и аудит. При изменении архива или файла нужно
повторить предпросмотр; параллельное применение не перезаписывает чужие правки.
Полный снимок берётся сервером из действующего архива, а не из файла пользователя.

При потерянном ответе проверьте файл заново: если записи уже сохранены, сервер
сообщит о существующих ID. Повторно создавать людей с другими ID не следует.
Импорт не требует новых переменных окружения, SDK или миграций базы.
