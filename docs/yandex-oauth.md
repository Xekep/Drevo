# Вход через Яндекс и роли

Единственный способ входа на сервере — Яндекс OAuth. Формы пароля и маршрута `/api/login` больше нет. Исходник: `src/server/yandex-oauth.ts`.

```text
GET  /auth/yandex
GET  /auth/yandex/callback
POST /auth/logout
```

В приложении Яндекса указывается точный Redirect URI: `https://drevo.kiiko.ru/auth/yandex/callback`. В `/etc/drevo.env` с правами `600` сохраняются `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`. Секрет не попадает в Git, сборку браузера и бэкапы семейной базы. `PUBLIC_ORIGIN` задан в systemd. После изменения окружения требуется перезапуск сервиса.

Авторизация использует одноразовые `state` и PKCE, проверку cookie браузера и серверный обмен кода на токен. По токену запрашивается постоянный `id` пользователя. Токен Яндекса не сохраняется. Имя профиля используется только для отображения; учётная запись идентифицируется по `id`.

## Первый администратор

Первый успешно авторизовавшийся Яндекс ID становится администратором. Выбор роли выполняется в транзакции `BEGIN IMMEDIATE` в SQLite: одновременные входы не создают несколько «первых» администраторов. Все следующие новые пользователи получают роль читателя. Повторный вход не меняет назначенную роль. Локальный режим не регистрирует Яндекс ID и не занимает место первого администратора сервера.

## Роли

| Роль          | Возможности                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| Читатель      | Смотреть древо, каталог семей, карточки и фотоальбомы                                                  |
| Родственник   | Всё для чтения, создание людей и фото, редактирование только своих карточек и фото                     |
| Администратор | Любые карточки и связи, удаление, импорт архива, управление ролями и публичностью, все резервные копии |

В **«Управлении»** администратор назначает читателя, родственника или администратора. Последнего администратора нельзя понизить. Роль перечитывается из базы при каждом запросе, поэтому изменение прав действует и для уже открытых сеансов.

Автор карточки `createdBy` назначается сервером. Родственник не может присвоить себе чужую карточку, удалить существующую карточку или изменить чужую через полный JSON-снимок. Он может указать уже известного родителя своей карточке ребёнка; брак, затрагивающий обе карточки, и дополнительные связи доступны между своими карточками. Старые карточки без автора редактирует администратор. Удаление оставлено администратору.

Сеанс — случайная cookie `HttpOnly`, `SameSite=Lax`, `Secure` на HTTPS, срок 90 дней. В SQLite (`auth_sessions`) сохраняются только SHA-256 токена, пользователь и срок действия. Токен не доступен JavaScript страницы и не записывается в базу в открытом виде. Вход сохраняется после закрытия браузера, перезапуска сервера и обычного деплоя.

При запросах к API активная сессия продлевается до 90 дней, не чаще раза в сутки. Истёкшие сессии не восстанавливаются; актуальная роль читается из базы при каждом запросе. `/auth/logout` удаляет сессию из SQLite и cookie браузера сразу, не выходя из аккаунта Яндекса. Повторный вход заменяет текущую сессию этого браузера. Проверки Origin и `Sec-Fetch-Site` для изменения данных сохранены.

После первого обновления с прежних сессий в памяти понадобится один повторный вход. Проверка `tests/sessions.test.ts` закрывает и заново открывает сервер с той же тестовой SQLite, проверяет продление, истечение, смену роли и отзыв при выходе.

Официальные источники: [Authorization Code, state и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [профиль Яндекс ID](https://yandex.ru/dev/id/doc/ru/user-information).
