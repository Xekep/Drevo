# Вход через Яндекс

Модуль находится в `src/server/yandex-oauth.ts`. Он добавляет три маршрута:

```text
GET  /auth/yandex
GET  /auth/yandex/callback
POST /auth/logout
```

## Настройка

Зарегистрируйте приложение в Яндекс OAuth. Адрес возврата должен точно совпадать:

```text
https://drevo.kiiko.ru/auth/yandex/callback
```

Для определения пользователя требуется доступ к его Яндекс ID; приложению достаточно данных профиля, без почты, телефона и Яндекс Диска. Настройте подходящее право профиля в интерфейсе регистрации Яндекса.

Добавьте в `/etc/drevo.env`:

```ini
YANDEX_CLIENT_ID=<идентификатор приложения>
YANDEX_CLIENT_SECRET=<секрет приложения>
YANDEX_ALLOWED_IDS=<разрешённый id,ещё один id>
```

В списке используются постоянные строковые `id` из API Яндекс ID, а не имя, почта или отображаемый логин. Если список пуст, OAuth отключён. После изменения настроек перезапустите `drevo.service`. Кнопка «Войти с Яндекс ID» появляется при наличии всех настроек. До этого `/auth/yandex` возвращает `503` с понятным сообщением; вход по паролю продолжает работать.

`PUBLIC_ORIGIN` уже задан в systemd как `https://drevo.kiiko.ru`. Для отдельного тестового приложения можно зарегистрировать локальный callback и задать соответствующий origin; не переносите рабочий Client Secret в браузер или Vite-переменные.

## Как работает

Первый маршрут создаёт случайный одноразовый `state` и PKCE-верификатор, хранит их до 10 минут и отправляет браузер на `oauth.yandex.ru/authorize`. Cookie состояния имеет `HttpOnly`, `SameSite=Lax` и `Secure` на HTTPS: Lax нужен для возврата со страницы Яндекса.

Callback проверяет состояние и cookie, обменивает код с PKCE на токен, получает профиль из `login.yandex.ru/info` и сверяет `id` со списком допуска. Только после этого создаётся обычный сеанс редактора Древа. Токен Яндекса не сохраняется в SQLite, cookie или браузере и не записывается в логи приложения.

`POST /auth/logout` завершает сеанс Древа; он не выходит из самого аккаунта Яндекса. Проверка Origin защищает выход, как и другие изменяющие запросы. Существующий `/api/logout` оставлен совместимым псевдонимом.

Состояние OAuth и сеансы находятся в памяти процесса: после перезапуска незавершённый вход нужно начать заново. Ошибки или отмена у провайдера не дают доступа к архиву.

Реализация основана на официальных инструкциях Яндекса: [код подтверждения, state и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [получение данных пользователя](https://yandex.ru/dev/id/doc/ru/user-information).
