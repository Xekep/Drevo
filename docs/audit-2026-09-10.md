## Архитектура: что оставить

- Разделение чистого `domain`, HTTP/SQLite в `server`, React-компонентов и хуков подходит проекту. Замена React, Node.js или SQLite для этих исправлений не нужна.
- Раскладка вынесена в Worker, ELK проверяется после сборки. Камера React Flow не обновляет весь `App` на каждом движении. Семейные союзы отделены от записей людей, поэтому повторное отображение человека не создаёт дубль в базе.
- Проверки прав выполняются на сервере; скрытые мобильные кнопки не считаются защитой API. Сохранение использует revision и транзакцию, клиент умеет разбирать конфликты.
- Восстановление бэкапа ограничивает размер, пути и типы записей TAR; в репозитории есть проверки прав, конфликтов и восстановления. Релиз активируется отдельным workflow с резервной копией.

## Проверки

- `npm run typecheck`, `npm run lint`, `npm test`: 135 тестов, включая начальное раскрытие панели и запрет production без корректного origin.
- `npm run build`, затем `npm run test:worker`: собранный Worker запускает ELK и переключается обратно в хронологию.
- `npm audit`: 0 известных уязвимостей после обновления. Сборка сохраняет предупреждения о крупных чанках и имени IIFE для вложенного Worker; запуск Worker проверен отдельно.
- Без входа опубликованные `/api/users`, `/api/settings`, `/api/backup`, `/api/backup/full` отвечают 401. Главная, health и разрешённый публичный JSON-экспорт отвечают 200. Проверены HSTS и SAMEORIGIN, HTTPS проходит проверку доверия клиента.
- В браузере остаётся проверить: движение одним пальцем и pinch с началом на линии в обоих режимах дерева; открытие, сворачивание и закрытие профиля; прокрутку длинной карточки; ориентацию экрана и нижнюю безопасную область; пролёт голубя при длинной фамилии, быстром переключении людей и `prefers-reduced-motion`.

Критерий визуальной приёмки: портрет круглый, текст сохраняет обычные отступы и переносы, птица не задерживает открытие профиля, а после закрытия панели дерево остаётся в прежнем обзоре.
