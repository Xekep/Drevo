# Оптимизация отрисовки древа

Раскладка в Worker и отрисовка сцены измеряются отдельно: время ELK не объясняет задержки перемещения уже построенного древа.

## Что оптимизировано

- Пересечения маршрутов кэшируются по геометрии рёбер. Выбор и подсветка связи не требуют повторно искать геометрические пересечения, пока маршруты не изменились.
- `PersonNode` и `RelationshipEdge` используют специализированные comparators и не перерисовывают внутреннее содержимое, когда их значимые входы не изменились.
- Layout worker переиспользуется между последовательными расчётами. Если активный расчёт уже устарел, worker завершается, чтобы старый ELK не конкурировал за CPU с новым расчётом.
- Ответы worker помечены `requestId`, поэтому устаревший результат не может подменить актуальную геометрию.
- Проекция layout по-прежнему содержит только данные, влияющие на геометрию дерева. Текстовые изменения человека не должны сами по себе менять ключ раскладки.

## Проверки

Добавлены отдельные тесты для кэша пересечений и comparator данных карточки человека. Полный `typecheck`, `lint`, `test` и `build` следует запускать перед слиянием в `main`.

## Профиль большого древа, 2 октября 2026

Проверена production-сборка на синтетической семье `randomFamily(5, 9)`:
977 человек, 1290 маршрутов, портреты, viewport 1280×720. Это семья с браками
между ветвями, а не тысяча несвязанных прямоугольников. Фотографии заменены
небольшими SVG-заглушками через тестовый HTTP-маршрут; декодирование реальных
фотографий и сеть пользователя этот замер не воспроизводит.

Браузер — Chrome 155, Windows, GTX 1070, аппаратные Canvas/GPU compositing/WebGL
включены. Для стресс-прогона CPU замедлен через CDP в 4 раза. Запись Playwright
trace отключена: обход DOM при каждом действии искажает измерения. Подробный
CPU-профиль включается отдельно, его запуск/остановка не входят в выборку rAF.

Общий обзор уже использует ограниченный размерами viewport Canvas 2D. При
600+ карточках и масштабе ниже 18% он рисует целую сцену; на меньших деревьях
рисует только миниатюры поверх HTML/SVG. В приближении работают React Flow
и отсечение невидимых элементов. Портреты 48×48 заранее обработаны и кэшируются;
во время движения камеры обзорный Canvas преобразуется одной CSS-матрицей,
затем перерисовывается после остановки.

Найденная лишняя работа: `hidden: true` не отключает внутренние подписки
React Flow. Скрытый `EdgeWrapper` всё ещё вычисляет позиции handles на каждом
обновлении store, а отключённое отсечение сохраняет скрытые `NodeWrapper`.
Обзорный режим теперь передаёт пустой массив рёбер и включает отсечение
скрытых узлов. Метаданные узлов и их размеры остаются для `fitView` и перехода
к человеку; маршруты Canvas и экспорт берут полную геометрию отдельно.

Один контрольный замер одинакового движения мыши туда и обратно (160 шагов),
после окончания раскладки и загрузки изображений:

| Масштаб и операция | До: JavaScript | После: JavaScript |
| --- | ---: | ---: |
| 5%, панорамирование | 3165 мс | 490 мс |
| 17,9%, панорамирование | 3097 мс | 426 мс |

Это суммарное время скриптов в жесте, не время одного кадра и не обещание
такого же ускорения на любом компьютере. В покое в том же стресс-прогоне
скрипты занимали около 12–13 мс за две секунды; непрерывного пересчёта layout
не обнаружено.

Оставшаяся проблема — HTML/SVG и переход между сценами. При 21,5% на экране
119 карточек, 284 связи, около 3940 DOM-элементов. В исходном стресс-прогоне
панорамирование имело p95 интервалов rAF 217 мс, пересечение порога 18% —
400 мс. После устранения скрытых подписок задержки в HTML/SVG сохранились:
большая часть времени уходит в работу браузера со стилями и отрисовкой.
Это обосновывает отдельный GPU-слой; производительность WebGL в Drevo пока
не измерена, сравнительного WebGL-прототипа в этом изменении нет.

### Следующий этап: единая сцена WebGL

1. Сохранить координаты и маршруты Worker; рисовать линии, портреты и подписи
   в одном слое при любом масштабе. При движении менять только матрицу камеры,
   без пересоздания карточек и загрузки геометрии в GPU каждый кадр.
2. Портреты объединять в ограниченные по размеру атласы текстур, подписи —
   в атлас глифов с кириллицей и SDF/MSDF. Избежать отдельной маски/фильтра
   и отдельной текстуры на каждого человека. Ограничить память, освобождать
   ресурсы при смене архива.
3. Сохранить существующие закругления/разрывы маршрутов, пунктир, выделение,
   оранжевую отметку проверки и реальные разрешённые URL портретов.
4. Оставить HTML для панели человека и небольшой интерактивной накладки:
   приватность, раскрытие ветви, клавиатура и мобильные действия. Проверку
   попадания выполнять по мировой геометрии, учитывая текущую камеру.
5. Рисовать по запросу, без вечного ticker в покое. Предусмотреть потерю
   WebGL-контекста и резервный текущий renderer. PDF/TXT и доступ по общей
   ссылке используют прежние границы данных.
6. Сравнить оба renderer на одной геометрии с реальными разрешёнными
   миниатюрами: 1000 и 3000 человек, обзор/средний/близкий масштаб,
   непрерывный zoom и панорамирование, память, rAF и задержка клика.
   Целевой порог первой проверки — p95 rAF до 33 мс на описанном desktop
   без искусственного замедления CPU; это критерий будущего прототипа.

Подходы для изучения: [Sigma: программы узлов/линий и атлас портретов](https://www.sigmajs.org/docs/advanced/renderers/),
[PixiJS: batching, текстуры и ограничения фильтров](https://pixijs.com/8.x/guides/concepts/performance-tips),
[PixiJS: BitmapText и SDF/MSDF](https://pixijs.com/8.x/guides/components/scene-objects/text/bitmap).
PixiJS — кандидат для прототипа сценического слоя. Sigma полезна как пример
пакетной отрисовки; её стандартные рёбра не заменяют специализированные
генеалогические маршруты Drevo. Зависимость renderer пока не добавлена.

### Воспроизводимый замер

После `npm run build`, в PowerShell:

```powershell
$env:DREVO_LAYOUT_SCALE_E2E = '1'
$env:DREVO_LAYOUT_SCALE_PORTRAITS = '1'
$env:DREVO_RENDER_PROFILE = '1'
$env:DREVO_RENDER_CPU_THROTTLE = '4' # 1 для обычного прогона
$env:DREVO_RENDER_PROFILE_TARGETS = '0.05,0.15,0.19'
npx playwright test tests/e2e/tree-scale-benchmark.spec.ts --project=desktop
```

Порт задаётся `DREVO_E2E_PORT`, внешний Chrome —
`PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Не включать одновременно другие специальные
режимы benchmark (`ALIGNMENT`, `KINSHIP`, `SLOW_THUMB`, `SCREENSHOT`, `CLICK`):
они меняют камеру или загрузку портретов. Без `PROFILE_TARGETS` проверяются
шесть масштабов. `DREVO_RENDER_CPU_PROFILE=1` добавляет CPU-профили в attachments;
полный прогон с замедлением CPU и профилированием может превысить лимит теста,
для него следует выбирать один-два масштаба. JSON с измерениями, сведения о GPU
и снимки состояний сохраняются в результатах Playwright; в production
инструментирование не входит.
