# Дорожная карта Drevo

Этот файл фиксирует крупные продуктовые направления, которые требуют нескольких связанных изменений. Мелкие исправления и полировка интерфейса по-прежнему идут обычными задачами.

## AI / Research API

Цель: превратить Drevo из средства просмотра семейного графа в инструмент генеалогического исследования. Вычисляемые факты формирует код Drevo, а языковая модель объясняет их, сопоставляет и предлагает направления дальнейшего поиска.

### Этап 1 — общий слой Research Tools

- [x] Единый каталог read-only инструментов в domain.
- [x] Поиск человека, карточка, ближайшая семья, предки и потомки.
- [x] Вычисление родства.
- [x] Источники карточек, событий и наград.
- [x] Поиск пробелов и уже реализованных вычисляемых противоречий.
- [x] Сводная статистика архива.
- [x] Фильтрация анализа по выбранной ветке, а не только по человеку или всему архиву.
- [x] Более сильный поиск вероятных дублей: варианты фамилий, неполные даты, места.
- [x] Исследовательский backlog с приоритетом ценности следующего документа.

### Этап 2 — ИИ-исследователь в веб-интерфейсе

- [x] Серверный endpoint, секрет AI Studio не попадает в браузер.
- [x] Tool calling использует тот же слой Research Tools.
- [x] Базовая панель чата с контекстом текущего раздела и выбранных людей.
- [x] Модель получает разрешённые фото только через отдельный проверяемый tool; face descriptors, аккаунты и служебные поля не получает.
- [x] Потоковый вывод ответа через SSE поверх POST с поддержкой tool-calling.
- [x] Кнопка «Анализировать ветку» с выбором глубины 2/4/6/8 поколений.
- [x] Отдельный отчёт полноты ветки и исследовательские рекомендации.
- [x] Ссылки из ответа ИИ обратно на карточки людей и источники.
- [x] Настройка модели и состояния AI Studio в админке.
- [x] Лимиты частоты/дневного использования и наблюдаемость по запросам, provider calls, токенам, ошибкам и задержке.

Конфигурация AI Studio задаётся из **«Админка → Yandex AI»**: API-ключ, Folder ID и модель из динамического списка каталога. MCP-токены находятся в отдельном разделе. API-ключ хранится в SQLite только в зашифрованном виде; локальный AES-ключ лежит отдельным файлом рядом с БД и не отдаётся браузеру.

Переменные окружения остаются резервным способом настройки:

- YANDEX_AI_API_KEY — API-ключ AI Studio.
- YANDEX_AI_FOLDER_ID — идентификатор каталога AI Studio.
- YANDEX_AI_MODEL — модель, если она не выбрана в админке.
- YANDEX_AI_BASE_URL — необязательно, по умолчанию https://ai.api.cloud.yandex.net/v1.

### Этап 3 — MCP

- [x] Stateless HTTP endpoint /mcp: modern MCP 2026-07-28 через server/discover и прямые вызовы; legacy-клиенты через initialize. Опубликованы tools/list и tools/call.
- [x] Реализация без дополнительной runtime-зависимости от MCP SDK; протокольный слой остаётся тонким адаптером.
- [x] Read-only инструменты используют тот же Research Tools слой.
- [x] Администратор выдаёт отдельные MCP-токены.
- [x] В базе хранится только SHA-256 токена; секрет показывается один раз.
- [x] Scopes: tree:read, sources:read, analysis:read.
- [x] Отзыв токена и срок действия.
- [x] Привязка токена к участнику с наследованием его области доступа, включая common_ancestors.
- [x] Аудит MCP-вызовов без записи чувствительных аргументов.
- [x] Ограничение частоты запросов на уровне отдельного MCP-токена.
- [x] CI-smoke через официальный @modelcontextprotocol/client v2: modern 2026-07-28 и legacy 2025-era.
- [x] Документированная конфигурация Yandex AI Studio MCP Hub: Streamable HTTP + Bearer token.
- [x] Nginx-конфигурация и публичный deployment-smoke для /mcp.
- [ ] Живой deployment-smoke через Yandex AI Studio MCP Hub на публичном HTTPS endpoint.

## Принципы

1. domain остаётся источником вычисляемых фактов; LLM не считается калькулятором или валидатором.
2. HTTP, веб-ИИ и MCP — адаптеры поверх одной прикладной логики.
3. Отсутствие записи не трактуется как доказательство отсутствия события.
4. Гипотеза, вычисляемое предупреждение и подтверждённый факт показываются раздельно.
5. Фотографии, отпечатки лиц, аккаунты и административные данные не отправляются модели без отдельной явной функции.
