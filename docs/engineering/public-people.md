# Публикация людей в поиске

Администратор открывает контекстное меню карточки человека и выбирает «Публикация в поиске». Опубликовать можно только человека с указанной смертью или подтверждённым статусом умершего. Публикация требует отдельного нажатия «Опубликовать в поиске»; создание временной ссылки не публикует карточку. Снять публикацию можно там же. Прямая ссылка после этого сразу перестаёт открываться. Если статус человека изменится на живущего или неизвестный, сервер перестанет показывать ранее опубликованную карточку.

Вошедшие пользователи ищут опубликованных людей на `/discover` даже без доступа к древу. До проверки сессии форма поиска и карточки не отображаются; гостю предлагается вход. В форме входа нет ссылки на поиск. Поиск и карточка показывают только ФИО, годы рождения и смерти, места рождения и смерти. Связи, фото, биография, документы, заметки и источники остаются закрытыми. Запросы ограничены по частоте; API поиска и карточек возвращает `401` без действующей сессии, включая истёкшие и отозванные сессии.

При возврате на вкладку проверка сессии повторяется: результаты временно скрываются, введённый текст сохраняется после успешной проверки. Завершение сессии или ошибка проверки убирают результаты; при ошибке доступна повторная проверка. Ответ `401` от поиска или карточки также возвращает экран входа. Это ограничение не меняет доступ по временным ссылкам на древо.

PostgreSQL использует межархивную проекцию опубликованных людей для `/api/discovery/people`. Старый `/api/published-people` сохраняется для SQLite и также требует входа. Доверенный локальный режим SQLite оставляет ответ `501` глобального поиска для перехода к старому API; это не разрешение анонимного доступа при внешнем обслуживании. SQLite создаёт таблицу `published_people` при обновлении схемы; PostgreSQL применяет `ops/postgres/019_published_people.sql` при запуске.
