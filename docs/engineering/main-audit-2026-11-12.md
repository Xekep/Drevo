### A-01. Успешная привязка источника не сохраняется

Место: [source-catalog-http.ts:141](../../src/server/source-catalog-http.ts#L141),
добавление в массив на строке 153, запись архива на строке 162.

`PersonEvent.sources` необязателен. Выражение `event.sources || []` создаёт
временный массив, если поле отсутствует. Последующий `push` меняет только
этот массив: он не присваивается обратно событию. Сервер отвечает 200 и
повышает revision, хотя источник у события не появляется. Для `sources: []`
тот же маршрут работает правильно.

Воспроизведение через настоящий локальный HTTP-сервер и отдельную SQLite:

1. Создать человека с двумя событиями: `{id: "a", type: "move"}` и
   `{id: "b", type: "move", sources: []}`.
2. Создать источник через `POST /api/sources`.
3. Для каждого события вызвать `POST /api/sources/<id>/links` с актуальными
   `personId`, `eventId`, `revision`; после каждого запроса прочитать архив.
4. Для первого события: HTTP 200, revision 3 → 4, сохранённых источников 0.
   Для второго: HTTP 200, revision 4 → 5, сохранённых источников 1.

Исправление: явно сохранять созданный массив в `event.sources`, сохранив
проверки дублей и конфликтов. Регрессия должна проверять отсутствующее поле,
пустой массив, повторное чтение, дубликат и устаревшую revision.
Текущий `source-catalog-http.test.ts` использует событие с `sources: []` и
поэтому не обнаруживает потерю.

### A-02. Неполные события по временной ссылке

Место: [shared-family.ts:90](../../src/domain/shared-family.ts#L90).
Доменные поля: [types.ts:69](../../src/domain/types.ts#L69).
Отображение: [person-events.tsx:603](../../src/components/person-events.tsx#L603).

`shareFamily` вручную перечисляет разрешённые поля события. В перечне нет:

- образование: `educationField`, `educationQualification`, `educationStatus`;
- работа: `organization`, `position`;
- служба: `militaryUnit`, `militaryRank`;
- переезд: `moveFrom`.

Воспроизведение: передать в `shareFamily` человека с четырьмя соответствующими
событиями и заполненными полями. В результате отсутствуют все восемь полей.
Проверен реальный доменный преобразователь, используемый публичной выдачей;
сохранённые данные исходного архива при этом не теряются.

Исправление: расширить явный список разрешённых полей и добавить контрактный
тест четырёх типов событий. Не заменять список безусловным `...event`:
публичная проекция должна продолжать исключать внутренние данные вложений.

### A-03. Неограниченная подготовка старого полного бэкапа

Места: [database-backup-http.ts:116](../../src/server/database-backup-http.ts#L116),
[full-backup.ts:31](../../src/server/full-backup.ts#L31), запуск TAR на строке 38.
Маршруты подключены в `archive-http.ts`; это действующий код.

`GET /api/backup/full` напрямую вызывает `fullBackup`. Каждый запрос создаёт
снимок, подготавливает файлы и запускает собственный TAR. На этой ветке нет
общей очереди, ограничения времени и AbortSignal подготовки. Проверка
полномочий перед выдачей сохранена, но отключение клиента до выдачи не
останавливает дорогую работу. Более новый управляемый путь бэкапов имеет
координатор и ограничения; старый маршрут их обходит. Соседний `/api/backup`
также напрямую создаёт снимок вместо использования общего допуска.

Доступ ограничен владельцем древа с глобальной ролью администратора или
исследователя; анонимный доступ и обход разрешений этим опытом не обнаружены.

Воспроизведение: три параллельных HTTP-запроса к синтетическому локальному
архиву; после запуска упаковщиков отменить все запросы. Получено:
`maximumActiveTar: 3`, `runningAfterAbort: 3`, `completedAfterAbort: 3`.
В отдельном процессе воспроизведения запуск настоящего TAR задерживался
на 350 мс для наблюдения отмены. Это управляемая задержка опыта, а не замер
производительности рабочего сервера. Код приложения не подменялся на диске.

Исправление: провести старые маршруты через существующий координатор и общий
допуск; связать подготовку с отменой/таймаутом и завершением дочернего процесса.
Проверить параллельные запросы, обрыв соединения, уборку файлов и повторный
запуск. Отмена одного потребителя не должна ломать общую задачу другого.

### A-04. Dev-зависимость minimatch

`npm audit` сообщает семь Moderate-записей, соответствующих одной исходной
проблеме minimatch и её распространению по цепочке `typescript-eslint`.
Вложенная установленная версия — 10.2.5; прямой dev-пакет
`typescript-eslint` — 8.59.3 (`package.json:105`).

Условия и исправленная версия приведены в
[GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).
Для уязвимого пути нужны управляемый атакующим glob и `optimizationLevel >= 2`.
Путь от пользовательского HTTP-запроса к этой dev-цепочке не установлен.
Runtime-манифест `ops/runtime` с `--omit=dev` имеет ноль advisory.

Подобрать совместимое обновление инструментов. Не применять автоматически
`npm audit fix --force`: предложенный аудитом переход на 8.36.0 меняет
версии инструментов и требует отдельной проверки.

файлов, которые можно сейчас безусловно удалить, среди них нет.
Граф учитывает статические и lazy-импорты, Worker URL и операционные точки
входа; он не доказывает отсутствие мёртвых экспортов или состояний интерфейса.

## Исправления после аудита

По поручению пользователя подготовлено техническое продолжение в
`codex/main-audit-fixes-20261112`:

- A-01: отсутствующий массив источников явно присваивается событию. HTTP-тест
  проверяет оба состояния поля, сохранённый JSON в БД, дубликат, удаление и
  отсутствие изменений при устаревшей revision.
- A-02: восемь полей добавлены в явную публичную проекцию. Тест проверяет все
  четыре типа событий вместе с исключением внутренних полей и attachment ID.
- A-03: оба старых маршрута используют существующий координатор, общую
  серверную квоту подготовки и 30-минутный deadline. Lease исключает
  параллельную подготовку через старый и управляемый API, включая другой
  экземпляр координатора. Снимок/санитизация/проверка выполняются в Worker;
  отключение клиента отменяет Worker и TAR. Lease не освобождается до `close`
  дочернего процесса. Подготовка заканчивается до начала выдачи; закреплённые
  файлы и квота подготовки сохраняются до конца передачи. При отмене
  незаконченной подготовки файлы удаляются до освобождения lease.
  Нормальное завершение HTTP не считается отменой. Скачивания не попадают
  в каталог retention и не меняют лимит хранимых копий.
- A-04: добавлен узкий override `@typescript-eslint/typescript-estree →
  minimatch 11.0.1`. Прямые версии ESLint сохранены; обновление не затрагивает
  runtime. Чистая установка и lint проверяют совместимость используемого API.
  Убрать override после перехода родительского пакета на исправленную ветку.

Добавлены проверки двух экземпляров координатора, отмены настоящего дочернего
процесса на стадиях snapshot/TAR, удаления временных файлов, нормального
скачивания и повторного запуска. PostgreSQL runtime-сценарий дополнен
проверкой общего lease старого и управляемого API через другой координатор.
Рабочие данные при подготовке исправлений не использовались.
