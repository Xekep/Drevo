# Управление древом

В «Настройках древа» владелец меняет название и описание. Новое древо при
регистрации или создании из ЛК называется «Семейный архив». Существующие
пользовательские названия сохраняются. Форма обрезает внешние пробелы и
защищает несохранённый черновик при уходе; сохранение использует обычную
проверку ревизии и не заменяет подробности людей и фотографий.

В «Общем доступе» остаётся каталог временных ссылок. Публичное открытие
всего архива и фотоальбомов отключено сервером. Старые флаги в восстановленных
данных не возобновляют доступ. В «Можно найти» основной список содержит
только опубликованных людей. Кнопка «Добавить в поиск» открывает отдельный
выбор подходящих неопубликованных людей. Предпросмотр публикации, выбор полей,
проверка владельца и отзыв через сервер сохранены.

В резервных копиях фиксирован лимит пять и доступно удаление с подтверждением.
Показывается счётчик сохранённых копий; менять их количество нельзя, в том
числе через API. После успешного создания шестой удаляется самая старая.
См. [резервирование](backup.md).

Пустая сцена завершает подготовку камеры без ожидания карточек; анимация
начального роста для неё не запускается. При последующем появлении карточек
работает обычная установка камеры.

## Адреса и удалённые рудименты

- Именной альбом: `/photos/<personId>`, с областью древа —
  `/a/<archiveId>/photos/<personId>`. Снимок: `/photo/<photoId>`.
  «Хроника» и «Добавить фото» находятся в общей панели действий альбома.
- Ссылки `?person=`, `?photo=`, `?personId=` и `?documentId=` для открытия
  сущностей больше не разбираются и не перенаправляются.
- Приглашение имеет вид `/join/<token>`. Длинный адрес с ID архива удалён.
- Управление архивом использует `/manage`, включая сопоставления. Прежние
  архивные `/admin` и `/admin/matches` не поддерживаются; `/admin` в корне
  остаётся действующей админкой платформы.
- Дубли адресов основного архива с `/a/<primaryId>/…` больше не
  перенаправляются на корневой маршрут: возвращается 404. Каталог древ
  сразу выдаёт правильный адрес.
- Общий поиск использует `/discover/search/<query>` и
  `/discover/person/<archiveUUID>/<personId>`. Query-адреса и карточка без UUID
  удалены. Неудача глобального API не переключает интерфейс на старый поиск
  внутри одного архива. Публичные адреса строятся по `archiveRouteId`.
- Удалена старая перегрузка `fullBackup` с отдельным путём и дополнительным
  HTTP-ответом; все вызовы используют текущую сигнатуру.

Проверка по назначению отделяет такие адаптеры от действующих функций.
Миграции схемы и переносимых копий, стандарты GEDCOM, SQLite как текущая
локальная СУБД, конфигурируемое наследование профилей ИИ, локальное хранение
генерируемых файлов и обработка ошибок загрузки не удаляются по совпадению
со словами `legacy` или `fallback`. В частности, одиночный ID файла ИИ всё
ещё выдаётся текущим SQLite-хранилищем, а переход на локальный расчёт раскладки
при недоступном серверном кеше — рабочая устойчивость, а не старый клиент.
