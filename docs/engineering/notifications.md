# Уведомления древа

Колокольчик рядом с меню аккаунта показывает новые карточки людей и новые
комментарии в обсуждениях людей текущего древа. Свои действия и системные
операции исключены. Уведомление ведёт к карточке; комментарий открывает её
вкладку «Обсуждение». Список содержит сохранённые события журнала, в том числе
события до появления колокольчика. Исторические сведения из полей журнала и
текст комментария в уведомление не включаются.

Колокольчик открывает компактный немодальный список под кнопкой. Он закрывается
по Escape или нажатию снаружи. Escape и кнопка закрытия возвращают фокус на
колокольчик; нажатие снаружи сохраняет фокус выбранного элемента.
Счётчик обновляется при открытии страницы/списка, возвращении в видимую вкладку
и раз в 30 секунд в видимой вкладке, включая открытый список. Это уведомления внутри
сайта, без push, писем и отдельного сервиса. Открытие списка само по себе не
помечает события прочитанными: переход отмечает одно событие, кнопка с двумя
галочками — все доступные события до полученного server watermark, включая
страницы, которые ещё не были раскрыты. Недоступные по ограниченной области
древа события не отмечаются. Событие, добавленное параллельно после получения
списка, остаётся непрочитанным. Список загружается страницами по 20.

Открытый список обновляет ранее загруженный диапазон последовательными запросами
по актуальным курсорам, без дубликатов и сохранения удалённых/ставших недоступными
записей. Стабильные ID сохраняют DOM строк и позицию прокрутки. Закрытому списку
достаточно одной головной страницы, поэтому догруженные ранее страницы не создают
постоянный фоновый трафик. Нет перекрывающихся poll; обновление ограничено десятью
секундами. Ошибка 401/403 очищает список и останавливает опрос до нового сеанса.

Звук включён по умолчанию и отключается кнопкой внутри списка; выбор сохраняется
локально отдельно для аккаунта. Только новая пачка непрочитанных событий при
фоновом обновлении даёт один короткий тихий тон. Первый ответ, повторное открытие,
догрузка страниц и отметки прочтения беззвучны. Монотонный watermark учитывает
ID всех полученных строк: поле `latest` сервера содержит максимум только среди
непрочитанных событий и после прочтения может уменьшиться до нуля.
WebAudio создаётся и разблокируется только доверенным нажатием/клавишей; до этого
браузер остаётся беззвучным. Ошибка autoplay или недоступность аудио не мешает
работе списка. Размонтирование убирает таймеры, слушатели и AudioContext;
маленькая keepalive-квитанция перехода по ссылке может завершиться после ухода
со страницы под прежними серверными проверками и собственным таймаутом.

## Хранение и доступ

`server/archive-notifications.ts` читает два вида подтверждённых событий из
существующего аудита. Запись данных и аудит уже выполняются одной транзакцией,
поэтому отклонённая операция не создаёт уведомления. Состояние прочтения
хранится отдельно для пары пользователь/архив: общий курсор и индивидуальные
квитанции, без копирования каждого события каждому участнику. SQL-миграция
`098_archive_notifications.sql` добавляет RLS и частичный индекс событий.

`GET /api/notifications?before=<id>` возвращает список, счётчик и курсор.
`POST /api/notifications` принимает только `{id}` или `{through}` для текущего
пользователя. Имя человека берётся из текущей карточки. Удалённые карточки и
комментарии не показываются; ограниченный участник видит события только о
доступных людях. Авторизованный сеанс, членство и текущая область видимости
проверяются внутри транзакции выдачи. HTTP-ответ ограничен пятью секундами.
Публичные ссылки и просмотр как участник не предоставляют персональный inbox.
У разных древ независимые счётчики и квитанции.

Проверки: `tests/archive-notifications.test.ts`, native PostgreSQL/RLS в
`tests/integration/postgres-shared-connections.ts`, desktop/mobile сценарий
`tests/e2e/archive-notifications.spec.ts`, чистые проверки прибытия/пагинации и
WebAudio в `tests/notification-arrivals.test.ts` и `tests/notification-sound.test.ts`.

## Памятные даты

При открытии колокольчика отдельный блок «Ближайшие памятные даты» показывает
годовщины смерти от сегодняшнего дня до семи дней вперёд включительно.
Переход открывает карточку. Блок не создаёт аудит, непрочитанные события или
повторный звуковой сигнал каждый день. Сохраняется в списке до конца дня памяти.
Это календарный блок внутри уведомлений, без отдельной отметки прочтения.

`GET /api/notifications?memorial=1&timeZone=Europe%2FMoscow` проходит те же
проверки сеанса, членства и области видимости, включая RLS и блокировку выдачи.
Текущий день вычисляется сервером в часовом поясе устройства, UTC при отсутствии.
SQL читает только ID, имена и даты смерти доступных людей, без полного снимка
архива, биографий и источников. Закрытый колокольчик не опрашивает этот маршрут.
Открытый обновляет его раз в минуту и при возвращении во вкладку; запросы не
перекрываются, ограничены десятью секундами, отменяются при закрытии/смене древа.
401/403 очищают календарный список и останавливают его опрос до нового открытия.

Только полная точная дата смерти даёт напоминание; текущий год смерти,
будущие, неизвестные и неполные даты исключаются. Для 29 февраля используется
28 февраля невисокосного года. Полная сохранённая григорианская дата пары
старого/нового стиля используется без нового пересчёта; неполная юлианская
дата не превращается в григорианский день. Идентификатор включает человека,
дату смерти и дату конкретной годовщины. Схема генеалогической базы не меняется.

Проверки: `tests/memorial-dates.test.ts`, дополнение HTTP-проверки
`tests/archive-notifications.test.ts`, `tests/e2e/memorial-notifications.spec.ts`.
