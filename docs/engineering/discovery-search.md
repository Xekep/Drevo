# Общий поиск опубликованных людей

`/discover` использует `/api/discovery/people`. Поиск требует действующего
аккаунта; членство в выбранном древе не требуется. Сервер читает только
явно опубликованную проекцию `discovery_people`, не приватный JSON людей.
Снятие публикации удаляет проекцию; перед выдачей страницы и связанных
карточек сервер удерживает и повторно проверяет нужные опубликованные строки.

Запрос содержит 2–100 символов, не более восьми слов. Регистр и ё/е
нормализуются; слова соединяются через И, используется префиксный полнотекстовый
поиск по опубликованным ФИО, годам и местам. Это не поиск по опечаткам.
Страница — 30 записей, курсор включает имя, внутренний ID древа и человека.
Карточки одного ID человека в разных древах не объединяются автоматически.

## Канонический адрес

Новые ссылки имеют вид `/discover/person/:archiveRouteId/:personId`, где
`archiveRouteId` — UUID. Существующий UUID древа сохраняется; старый технический
ключ вроде `legacy-primary` получает постоянный UUIDv8 через
`server/discovery-archive-id.ts`. Пространство имён и кодирование закреплены
тестом, их нельзя менять после публикации ссылок. Это публичный идентификатор
маршрута, не секрет и не разрешение доступа. Внутренний ключ БД, файлы и
ссылки между дрёвами не переименовываются.

API сохраняет внутренний `archiveId` для операций с опубликованными карточками
и отдельно передаёт `archiveRouteId` для ссылок. Страницы принимают только UUID
древа в адресе; прежние служебные ключи и query-ссылки не поддерживаются.
Разрешение UUID внутреннего архива
читает только опубликованные записи данного человека; миграция 112 добавляет
частичный индекс `person_id` только для старых ключей, включая UUID в верхнем
регистре. Обычные UUID читаются по составному первичному ключу; фоновой обработке
имён не навязывается общий `person_id`-индекс вместо keyset-прохода.
Перед самой выдачей остаются прежние проверки версии,
публикации и связанных карточек.

Проверки охватывают авторизацию, пагинацию, одинаковые ID разных архивов,
отзыв публикации, повторные проверки сеанса, канонизацию адреса и PostgreSQL/RLS.
Проверки браузера с подставленными ответами не заменяют PostgreSQL-интеграцию.
