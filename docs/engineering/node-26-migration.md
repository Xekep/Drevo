# Переход на Node.js 26 LTS

Целевая версия — **26.13.0 Lithium LTS**, закреплённая в `.nvmrc`.
[Официальный релиз от 28 октября 2026](https://nodejs.org/en/blog/release/v26.13.0)
указывает зависимость Linux-бинарников от `libatomic`. Подготовка сервера
проверяет наличие `libatomic.so.1` и при необходимости ставит `libatomic1`.

## Изменения репозитория

- GitHub Actions читает версию из `.nvmrc` для сборки, unit/browser-проверок,
  PostgreSQL и HTTP soak. Манифесты разработки и runtime требуют `>=26.13.0 <27`.
- Типы Node обновлены до 26.x. Тесты учитывают более строгие типы сообщений
  assert, необязательный IPC disconnect и возвращаемое значение async iterator.
- Основные npm-команды и systemd запускают TypeScript без экспериментального
  флага: в Node 26 удаление типов включено и стабильно. Исторические команды
  с `--experimental-strip-types` остаются совместимыми.
- Установка зависимостей релиза выполняется заново на целевом Node;
  `node_modules` со старого сервера в новый релиз не копируется.
- `.nvmrc` входит в артефакт релиза. `ops/deploy.sh` сравнивает реальный
  `/opt/drevo-node/bin/node` с этой версией **до** бэкапов, миграций, смены
  активного релиза и перезапуска. Несовпадение останавливает деплой.

## Существующий сервер

Изменения репозитория сами по себе не обновляют установленный `/opt/drevo-node`.
Перед активацией релиза с Node 26 оператор должен:

1. Дождаться зелёных Linux CI, PostgreSQL runtime/restore и браузерных проверок
   на целевой версии. Сохранить актуальный проверяемый бэкап и путь, на который
   сейчас указывает `readlink -f /opt/drevo-node`.
2. Из проверенного checkout запустить от root `bash ops/setup-server.sh`.
   Скрипт устанавливает бинарник рядом со старым, проверяет запуск и меняет
   `/opt/drevo-node`. Уже работающий процесс этим не перезапускается.
3. Проверить `/opt/drevo-node/bin/node --version`, обновить systemd unit из
   `ops/drevo.service` и выполнить `systemctl daemon-reload`.
4. Активировать проверенный релиз штатным workflow. Предварительные проверки
   существующего деплоя проверяют совместимость нового и предыдущего кода
   с копией базы; рабочие данные для тестов не используются.
5. Проверить health с ожидаемым releaseId, вход, PostgreSQL, загрузку фото,
   документы/PDF, создание копии и её изолированное восстановление.

При неудаче штатный deploy возвращает предыдущий код. Если причина в runtime,
оператор также возвращает `/opt/drevo-node` на сохранённый путь старого Node
и перезапускает сервис. Старый бинарник не удаляется при установке нового.
Требования к совместимости БД и восстановлению остаются прежними.

## Проверка и ограничения

Сервер обновлён 3 ноября 2026 года. Первую доставку после изменения `.nvmrc`
остановила проверка версии: production оставался на Node 22.23.2. Node 26.13.0
установлен рядом с ним из официального архива после проверки SHA256;
`/opt/drevo-node` переключён атомарно. Перед переключением сохранены свежий
нативный PostgreSQL dump, прежний путь runtime/релиза и unit в закрытом
каталоге `/root/drevo-node26-upgrade-*`. Старый бинарник
`/opt/node-v22.23.2-linux-x64` сохранён для отката.

В существующем unit удалён только `--experimental-strip-types`, выполнен
daemon-reload; ограничения сервиса, drop-in и sudoers сохранены. Подготовка
runtime сама работающий процесс не перезапускала. Повтор упавшей задачи
штатного workflow активировал проверенный артефакт
`d41ef0a918c585a88d7fd38f5200daf8d1b9e0df-1`. Бэкап/изолированное восстановление
PostgreSQL и совместимость обоих релизов прошли уже на Node 26. Внешний health
подтвердил этот releaseId; `/proc/<MainPID>/exe` указывает на новый бинарник,
самопроизвольных перезапусков после активации не было.
Страница входа проверена в Chromium на desktop и с эмуляцией Pixel 5:
HTTP 200, без JavaScript-ошибок и ответов 5xx. Вход в аккаунт и изменения
пользовательских данных на production для этой проверки не выполнялись;
авторизованные сценарии проверены Linux CI на изолированных данных.

Локальный runtime для миграции — Windows, Node 26.13.0. Его результаты
не заменяют Linux CI или проверку установленного серверного Node.
В окружении первоначально первым в PATH был TAR из WinAVR 2010 года:
он ломал архивирование независимо от Node. Для тестов используется системный
Windows TAR. Изображения наград взяты из артефакта CI того же проверяемого
коммита, пользовательские файлы не используются.

Vite 8.2.4 может выдавать DEP0205 при использовании устаревшего
`module.register()` внутри своей загрузки модулей. Это предупреждение
зависимости; его не скрываем и не исправляем патчем в node_modules.

Linux CI выявил прерывание процесса при сборке мусора незакрытого FileHandle:
браузер успевал отменить загрузку до завершения async open/stat. Обработчики
статики и публичных портретов теперь закрывают дескриптор в finally, независимо
от состояния ответа. Регрессия проверяет отмену ответа до открытия файла и
закрытие всех дескрипторов до возврата обработчика; до правки оба теста падали.
