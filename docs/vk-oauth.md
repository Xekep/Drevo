# Вход через VK ID

Drevo поддерживает два независимых способа входа: Яндекс и VK ID. На экране закрытого
архива и в личном кабинете отображаются две кнопки с логотипами. Отдельной кнопки
«Войти» в верхней панели нет. Ненастроенный провайдер виден, но его кнопка недоступна.

## Подключение

1. Создайте веб-приложение в кабинете VK ID и укажите домен сайта.
2. Зарегистрируйте точный redirect URI: `https://mydrevo.org/auth/vk/callback`
   (замените origin на свой).
3. Задайте на сервере `PUBLIC_ORIGIN=https://mydrevo.org` и `VK_CLIENT_ID=<ID приложения>`.
   Перезапустите сервер. Значения без префикса `VITE_`; `.env.example` служит образцом,
   а не хранилищем рабочих credentials.
4. Проверьте реальный вход на зарегистрированном домене. Автотесты подменяют ответы VK;
   они не проверяют настройки приложения или доступность VK для реального аккаунта.

Используется Authorization Code + PKCE S256 без клиентского SDK и без секрета VK.
Endpoint входа: `https://id.vk.ru/authorize`; обмен кода: `/oauth2/auth`; профиль:
`/oauth2/user_info`. При обмене обязательны `device_id`, одноразовый `code_verifier`
и `state`. Формат проверен по [официальной реализации VK ID](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts)
и [типам ответов](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/types.ts).
Телефон и email не запрашиваются; access/refresh tokens не сохраняются и не передаются
браузеру. Сессия Drevo — прежняя серверная сессия с HttpOnly cookie.

## Аккаунты и доступ

VK-пользователь хранится как `vk:<user_id>`. Существующие идентификаторы пользователей
Яндекса не меняются. Одинаковые числа или имена у разных провайдеров не объединяют
аккаунты автоматически. Связывание двух способов входа с одним аккаунтом здесь
не реализовано. Новому VK-аккаунту нужен допуск администратора; он не получает
администратора даже при первом входе. Первоначальный владелец по-прежнему задаётся
через `INITIAL_ADMIN_YANDEX_ID` — см. [настройку Яндекса](yandex-oauth.md).

## Реализация и проверки

`oauth-flow.ts` переиспользует существующие хранилище транзакций и ограничение попыток
входа для обоих провайдеров. State привязан к браузеру, провайдеру и сроку 10 минут,
потребляется один раз. Для VK и Яндекса используются отдельные cookie; токен VK
дополнительно проверяется по возвращённому state и идентификатору профиля. Внешние
запросы ограничены общим таймаутом 15 секунд. Ошибки возвращаются без внешних ответов,
токенов и stack trace; query callback не попадает в журнал запросов.

`tests/vk-oauth.test.ts` проверяет PKCE, пропущенный/просроченный/повторный state,
изоляцию провайдеров, device ID, несовпадение профиля, отказ VK, timeout, rate limit,
некорректный ответ и выдачу сессии без доступа к закрытому архиву. Существующие тесты
Яндекса проверяют общий механизм после выделения `oauth-flow.ts`.
