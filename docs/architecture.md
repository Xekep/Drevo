# Архитектура

Временные выдачи и журнал вынесены в `server/shares.ts`, `server/sharing-http.ts`, `server/audit.ts`; публичная ветвь открывает отдельный `SharedTree`, который не загружает общий архив. События хранятся внутри карточки и приходят со страницами подробностей. GEDCOM разбирается чистым `domain/gedcom.ts`, предпросмотр и применение — `server/gedcom-http.ts`. [Ссылки](sharing.md), [аудит](audit.md), [события](person-events.md), [GEDCOM](gedcom.md).

Браузер отображает React-приложение. Node.js раздаёт сборку Vite и обрабатывает HTTP API. SQLite хранит семейные сведения, а фотографии лежат рядом с базой в каталоге `uploads`. Облачные базы и внешние сервисы для работы не требуются.

Основное полотно построено на React Flow; разделы, поиск и добавление объединены в одну верхнюю строку, выбранный объект — в отдельной панели справа. На телефоне разделы сворачиваются в меню, панель открывается снизу, доступен только просмотр. Редактирование включается при ширине от 900 CSS-пикселей и наличии точного указателя. `/admin` — отдельная страница того же приложения для компьютера, с разделами участников, доступа и резервных копий. Все административные API проверяют роль на сервере; размер экрана не заменяет проверку прав.

## Разделение исходного кода

Маршруты разделов описаны в `domain/archive-routes.ts` и используются браузером и сервером: `/tree`, `/people`, `/families`, `/photos`, `/places`, `/admin`; `/` остаётся адресом древа. `useArchiveView` обновляет History API и обрабатывает `popstate`. Сервер отдаёт `index.html` только для известных страниц (в том числе с завершающим `/`); неизвестные адреса и отсутствующие файлы сохраняют `404`. Nginx уже проксирует эти пути, новая конфигурация не требуется. URL сохраняет раздел, но не черновики, выбранный альбом или положение камеры.

`domain/places.ts` собирает географические события, не меняя исходные названия; `server/geocoding.ts` выполняет последовательный поиск и кэширует ответы. Карта Leaflet загружается отдельным модулем. `domain/dates.ts` разделяет пользовательский ввод, каноническое хранение и границы неточных дат. `server/restore.ts` проверяет резервный файл в `shared/staging`, затем применяет семейные данные через действующее хранилище с проверкой ревизии; аккаунты не заменяются. OAuth state, GEDCOM preview и restore preview хранятся в SQLite, поэтому подтверждение можно обработать после restart или в другом процессе, работающем с той же базой и файловым каталогом.

Весь исходный код находится в `src`. `domain` не зависит от React, HTTP или базы: его функции используют и браузер, и сервер. `components` отвечает за отображение и формы, `hooks/useArchive.ts` — за запросы, контроль версии и состояние сохранения. `server` содержит HTTP-маршруты, хранилище, авторизацию и резервное копирование.

В разработке Node.js подключает Vite как middleware. В рабочем режиме `npm start` раздаёт готовый `dist` без Vite и без компиляции на сервере. `index.ts` создаёт один static handler с явным признаком режима и передаёт его в общую HTTP-цепочку после API, OAuth и media; отдельного production fallback после этой цепочки нет. Сервер использует встроенный `node:sqlite` и Sharp для WebP; React уже включён в сборку браузера. Серверные зависимости устанавливаются по отдельному lock-файлу `ops/runtime` при подготовке релиза.

`domain/archive-projection.ts` отделяет начальный граф от тяжёлых полей; `data/archive-pages.ts` собирает согласованные страницы. Частичный снимок доступен только для чтения. Подробности и ограничения — в [описании загрузки](loading.md).

`server/people-search.ts` обслуживает короткие AJAX-ответы по ФИО, обновляя кэш после смены ревизии. `server/image-previews.ts` создаёт и кэширует производные WebP, не изменяя оригиналы. `components/portrait-cropper.tsx` обрезает оригинал для отдельного портрета, а `components/gallery.tsx` разделяет просмотр и редактирование. Альбомы, подписи и географическая группировка — чистые функции в `domain`.

## Сохранение

Клиент получает семейный архив и его `revision`. Изменения отправляются полным снимком JSON с заголовком `If-Match`. Сервер проверяет структуру и связи, открывает транзакцию `BEGIN IMMEDIATE`, сверяет версию, сохраняет предыдущий снимок в историю и записывает новый граф. При несовпадении версии возвращается `409`; чужие изменения не перезаписываются.

Интерфейс обновляет данные после подтверждённого сохранения. При конфликте клиент сверяет изменения отдельных полей с актуальным снимком; независимые правки объединяются, совпавшие поля показываются пользователю. Отмена хранит до 20 наборов изменений текущей вкладки. Перед отправкой и на сервере итоговый граф проверяется целиком. Ограничение JSON-запроса — 8 МБ, количество людей — до 10 000; плавность больших деревьев зависит от устройства.

## Время и расположение

«Древо» использует `domain/union-layout.ts`: отдельные блоки точных союзов, визуальные отображения с общим `personId`, ELK Layered с фиксированными входами людей и общим выходом семьи к детям. `domain/family-packing.ts` собирает терминальных детей под родителями и сравнивает варианты для широких деревьев. Люди одного поколения не обязаны находиться на одной высоте. При нескольких союзах или цикле проекции появляются отмеченные карточки-ссылки. Усыновление остаётся дополнительной связью и не смешивается с биологическими родителями. «Хронология» использует реальные годы рождения, автоматически разводя близкие даты по колонкам. Служебные `generation` и `column` сохранены для совместимости, но новая раскладка от них не зависит.

`components/tree/use-family-view.ts` хранит область просмотра. `domain/family-neighborhood.ts` определяет ближайшую семью, раскрываемые связи и защищённые пути между выбранными людьми. `use-tree-layout.ts` передаёт Worker только эту проекцию и отменяет устаревшие запросы. В полном обзоре расчёт охватывает весь архив. [Семейный обзор](family-focus.md).

`components/tree/layout.worker.ts` использует асинхронную раскладку союзов `domain/union-layout.ts`. Для хронологии её результат преобразуется в `domain/union-timeline.ts`, где известные даты задают положение по Y, а неизвестные находятся отдельно от эпох. `timeline-positions.ts` перемещает семейные блоки целиком по X, `timeline-routing.ts` строит линии пар и детей с повторной прокладкой конфликтующих ветвей, `routing-quality.ts` оценивает кандидатов. [Алгоритм и пределы вычислений](timeline-layout.md). ELK включён в сборку Worker и не нужен Node.js на рабочем сервере. Раскладка не записывает предполагаемые годы и родителей в архив. Одинаковые координаты используются для карточек и SVG-связей. Полноразмерный Canvas удалён, включено отображение видимых элементов React Flow.

Начало шкалы расширяется при добавлении предков, родившихся раньше 1830 года. Эпохи задаются в `domain/layout.ts`. Это общий исторический фон, а не определение гражданства или территории для каждого человека.

`tree_settings.reverse_timeline` меняет направление времени для всех. `treeGeometry` переворачивает уровни и хронологию; интервалы эпох остаются положительными. Линии родителей выбирают стороны подключения по фактическим координатам карточек.

Жестами управляет React Flow. Камера изолирована внутри `components/tree`; её изменения не обновляют оболочку и формы. Выбор людей хранится в `useWorkspaceSelection`, черновики — в редакторах. Короткие правки выполняются в правой панели. Сценарии без перетаскивания сохранены. [Границы компонентов, жесты и отмена](tree-workspace.md).

## Стартовые данные

Новые базы создаются пустыми. Прежний пример семьи перенесён в `tests/fixtures/family.json` и не публикуется. Миграция `server/demo-cleanup.ts` однократно убирает известные стартовые карточки без автора, их связи и отметки. Проверяются идентификатор, имя, фамилия и дата рождения; очистка работает и после снятия признака демонстрационного архива. Добавленные карточки, фотографии, участники и настройки сохраняются. Предыдущий снимок остаётся в истории, перед деплоем создаётся резервная копия SQLite. Таблица `migrations` отмечает выполненную очистку.

## Фотографии

Сервер принимает бинарный файл, проверяет сигнатуру JPEG/PNG/WebP/GIF и назначает случайное имя. Пути к файлам не берутся из имени, переданного пользователем. Отметки хранят координаты от 0 до 1, поэтому масштабирование изображения сохраняет положение рамок. Портрет `Person.photo` независим от отметок галереи.

Удаление фотографии из галереи убирает запись и отметки; физический файл остаётся для истории и резервного восстановления. Автоматической очистки неиспользуемых снимков нет.

## Добавление новой связи

Обновите типы в `domain/types.ts`, проверку в `validation.ts`, названия и операции в `mutations.ts`, вывод родства в `kinship.ts`. Для нового типа прямого ребра также нужна миграция ограничения `relations.type` в SQLite: простого изменения `CREATE TABLE IF NOT EXISTS` для уже созданной базы недостаточно. Добавьте тесты обоих направлений и неполных данных.

`openArchive()` до создания любых хранилищ вызывает `initializeArchiveSchema()` из `server/schema.ts`. Это единственный источник DDL основной SQLite-базы: последовательные миграции создают core- и служебные таблицы, индексы и обновляют `PRAGMA user_version` внутри транзакций. Store-модули содержат только runtime-запросы и начальные строки настроек; очистка стартового примера сохраняет свой marker как data-логику. Запись архива не затрагивает аккаунты и настройки. Сервер проверяет роль и авторство при каждом изменении. Новую структуру добавляют отдельным переходом `vN → vN+1`, не редактируя уже опубликованные миграции, и проверяют восстановлением из бэкапа.
