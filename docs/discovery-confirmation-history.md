# История подтверждения межархивной связи

При первом подтверждении запроса сервер в той же транзакции сохраняет автора и время решения в `discovery_match_requests`, проверенный token, версии двух публикаций и отдельные значения только тех полей, которые были явно опубликованы на обеих карточках. Снимок нельзя изменить или дополнить после фиксации транзакции. Для связей, подтверждённых до миграции 086, история помечена как недоступная: сегодняшние значения не выдаются за прошлые.

Список запросов показывает участникам пары текущую опубликованную проекцию и, пока связь активна и обе карточки опубликованы, доступные части снимка. Для каждого исторического поля RLS дополнительно требует, чтобы это поле присутствовало с непустым значением в текущей разрешённой проекции. При отзыве поля или очистке его значения старое значение исчезает из HTTP и прямого чтения SQL; при отзыве карточки или связи скрывается весь снимок. Проверенный token хранится для аудита в БД, но не выдаётся по HTTP: он включает и те значения, разрешение на которые могло быть отозвано. Изменения после подтверждения перечисляют только названия разрешённых сейчас полей, без старых и новых значений в перечне изменений. Финальная проверка сеанса, членства, владельца, публикаций и запроса удерживается до завершения ограниченного по времени JSON-ответа.

Обычная правка карточки не разрывает подтверждённую identity-связь и не отзывает отдельные гранты. Исторические строки хранятся вместе с запросом и каскадно удаляются при удалении запроса или архива; отзыв публикации делает их недоступными, но сохраняет закрытый аудит до удаления архива. При удалении аккаунта существующая функция обезличивает `requested_by` и `responded_by` в запросе; отдельной копии идентификаторов автора в снимке нет. Предложения обновить уже скопированные поля остаются отдельным этапом.
