# Проверки исправлений полного UI-аудита

10 октября 2026 года. [Описание исправлений](../../ui-audit-full-fixes-2026-10-10.md).
Это локальные результаты; публикацию на сервере они не подтверждают.

## Автоматические проверки

| Проверка | Результат |
| --- | --- |
| Полный `npm test` | 1314 passed, 2 skipped, 0 failed; 1316 всего |
| `npm run typecheck` | exit 0 |
| `npm run lint` | exit 0, без предупреждений |
| `npm run build` | exit 0; существующее предупреждение о крупных lazy-чанках сохранено |
| `npm run test:worker` | 3 passed, 0 failed |

| Проверка после регрессии, обнаруженной полным CI (`admin-layout ui-full-audit-regressions`) | 18 passed, 2 skipped, 0 failed; 59,6 секунды |

Серии пересекаются: их результаты нельзя складывать как число уникальных тестов.
В более раннем широком запуске также прошли 46 проверок PDF/сканов и документов
на desktop/mobile. Его четыре ошибки были в новых тестовых ожиданиях и данных:
селектор меню, повреждённая PNG и штатное значение ECharts `animation: "auto"`.
После исправления тестов финальная серия завершилась без ошибок.

Финальная серия использовала актуальный production build, отдельную
синтетическую SQLite, установленный Chrome и мобильный проект Playwright (Pixel 5).
Для воспроизведения в PowerShell после обычной установки зависимостей:

```powershell
npm run build
$env:DREVO_E2E_PORT = '4173'
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npx playwright test ui-full-audit-regressions source-catalog email-auth-admin gallery-album-links guest-tree-preferences tree-generation-settings --workers=1
```

Playwright сам поднимает локальный сервер и создаёт тестовые данные. Production
данные не используются. Исходные проверки предыдущего UI-аудита
`tests/e2e/ui-audit-regressions.spec.ts` сохранены; новая серия находится отдельно,
в `tests/e2e/ui-full-audit-regressions.spec.ts`.

## Визуальная проверка

[states.json](states.json) содержит замеры ширин 320, 360, 390, 768, 1024,
1440 и 1920 px для каталога людей и хронологии, а также форм поиска документа
и мобильной загрузки фото на 390 px. Во всех 16 состояниях переполнение
корневой страницы равно 0 px; ошибок JavaScript не было.

Высота заполненной мобильной строки каталога на этом наборе — около 106 px
(до исправления в аудите — около 145 px); длинные имена переносятся.
Это измерение синтетических строк, не фиксированная высота всех пользователей.
Подписи хронологии проверены по вычисленным стилям: 12 px, цвет `#52634e`.

Сохранены четыре показательных снимка:

- [Каталог людей, 390 px](people-390.png).
- [Хронология, 390 px](timeline-390.png).
- [Поиск людей в форме документа, 390 px](document-search-390.png).
- [Загрузка фотографии, 390 px](photo-upload-390.png).

На снимках только тестовые данные. Снимок загрузки сделан после появления
диалога; одной задержки после клика недостаточно для проверки lazy-компонента.

## Что не проверено

Реальные мобильные устройства, Safari, экранные дикторы, доставка писем SMTP
и качество ответов реальной модели Yandex AI не проверялись. Ответы ИИ и
глобальные настройки email в E2E синтетические. Сложное редактирование рамок
лиц на touch-устройствах остаётся отдельной задачей.
