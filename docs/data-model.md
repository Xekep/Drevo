# Модель данных и родство

Корневой объект `Family` содержит `title`, `description`, `demo`, `people`, необязательные `links` и `photos`. Точные типы находятся в `src/domain/types.ts`.

## Люди

| Поле                                    | Содержание                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------- |
| `id`                                    | Постоянный уникальный идентификатор                                                   |
| `surname`, `name`, `patronymic`         | Фамилия, имя и отчество                                                               |
| `sex`                                   | `m`, `f` или `u` (не указан), для грамматической формы родства                        |
| `birth`, `death`                        | `YYYY-MM-DD` или `YYYY`; `birth: ""` — дата неизвестна, смерть необязательна          |
| `birthPlace`, `deathPlace`              | Места рождения и смерти                                                               |
| `maidenName`, `occupation`, `biography` | Фамилия при рождении, занятие и биография                                             |
| `photo`                                 | Ссылка на отдельный портрет                                                           |
| `parents`                               | Идентификаторы кровных родителей                                                      |
| `parentageComplete`                     | Явно известно, что указаны все кровные родители                                       |
| `spouses`                               | Идентификаторы супругов                                                               |
| `generation`, `column`                  | Прежние служебные поля; сохранены для совместимости, новая раскладка их не использует |
| `sources`                               | Название, тип, архивный шифр, ссылка и примечание источника                           |

Для добавления через интерфейс достаточно фамилии и имени. Отчество, дата рождения и пол могут быть неизвестны. Форма заполняет остальные служебные поля автоматически; пустая дата рождения хранится как `""`, неизвестный пол — как `"u"`. У таких карточек не показываются вымышленные возраст или год рождения; они располагаются отдельно от исторической шкалы. При наличии только года возраст показывается приблизительно.

Указанные даты в будущем, невозможные календарные даты, неизвестные ссылки и циклы родителей отклоняются. Возраст родителей и детей проверяется, когда известны обе даты рождения. `maidenName` сохраняет подтверждённую фамилию при рождении. Форма может предложить вариант по фамилии указанного отца; запись происходит только после подтверждения. [Подсказки по ФИО](name-hints.md).

## Дополнительные связи

`FamilyLink` содержит `id`, `from`, `to`, `type` и необязательный `note`.

| `type`            | Направление                                |
| ----------------- | ------------------------------------------ |
| `adoptive_parent` | Приёмный родитель → ребёнок                |
| `godparent`       | Крёстный родитель → крестник / крестница   |
| `nurse`           | Кормилица → вскормленный ребёнок           |
| `guardian`        | Опекун → подопечный                        |
| `sworn_sibling`   | Названые брат / сестра; симметричная связь |

Кровный родитель и супруг вводятся в том же редакторе, но хранятся в `parents` и `spouses`. Производные термины — например, свекровь или деверь — не записываются вручную: они рассчитываются из исходных связей.

## Как определяется родство

Алгоритм сначала ищет прямое происхождение и общих кровных предков, затем цепочки через брак. Результат содержит роли обоих выбранных людей, объяснение и путь в графе. Сводные братья/сёстры отличаются от единокровных и единоутробных. Неполные данные о родителях не превращаются автоматически в утверждение о неполнородном родстве.

Если пол не указан, расчёт пробует определить его по имени и отчеству, не меняя старые записи в базе. Если и этого недостаточно, используются нейтральные обозначения или обе формы. Для терминов свойства проверяется пол только нужных участников: например, неизвестный пол общего родителя не мешает назвать брата мужа деверем. Ручное уточнение пола имеет приоритет над подсказкой.

Явно записанное усыновление, духовное и молочное родство учитываются отдельно. Если люди одновременно кровные родственники и, например, крёстный с крестником, дополнительная связь выводится вместе с основной. Для длинных смешанных цепочек без однозначного русского термина показывается документированный путь. Отсутствие найденного пути не означает отсутствие родства в действительности.

Термины сверялись со словарями «Грамоты»: [термины родства и свойства](https://gramota.ru/journal/stati/zhizn-yazyka/terminy-rodstva-i-svoystva-v-russkom-yazyke), [дядя](https://gramota.ru/meta/dyadya), [кум](https://gramota.ru/meta/kum), [молочный](https://gramota.ru/meta/molochnyy), [побратим](https://gramota.ru/meta/pobratim). Разговорные и устаревшие варианты, например «ятровка», показываются как пояснения там, где они реализованы. Полного словаря всех диалектных и исторических названий проект не заявляет.

## Галерея

`ArchivePhoto`: `id`, локальный `url`, `title`, год `year` (строка из четырёх цифр), место `place`, событие `event`, уточнение даты/периода `takenAt`, `description`, массив `tags`. Все описательные поля, кроме названия, необязательны; пустые строки в просмотре скрыты. Старые записи без новых полей поддерживаются.

`PhotoTag`: `id`, `personId`, `x`, `y`, `width`, `height`. Координаты нормализованы относительно исходного изображения; рамка обязана целиком находиться в диапазоне `[0, 1]`. Один человек может быть отмечен на нескольких фото. Удаление человека удаляет его отметки, сохраняя снимки.

## Таблицы SQLite

`archive` хранит метаданные и версию; `people` — карточки; `relations` — нормализованные связи с внешними ключами; `photos` — сведения о снимках; `photo_tags` — отметки и ссылки на людей; `history` — последние 50 снимков семейных данных. `users` хранит пользователей Яндекса и роли, `access_settings` — публичность разделов. `createdBy` у человека, фото и дополнительной связи определяет автора; записи без автора редактирует администратор. Включены внешние ключи, WAL и индексы для входящих связей и отметок людей.
