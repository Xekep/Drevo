# Резервные копии и восстановление

В коде разделены два вида копий. Фактическую настройку оператора, расписания и внешнего хранилища проверяют на сервере отдельно; интерфейс не доказывает успешного резервирования.

## Копия выбранного древа

/manage → Резервные копии доступен только одобренному владельцу архива с явной глобальной ролью admin/researcher. Обычный владелец, читатель и режим «глазами участника» доступа не получают. Тариф не заменяет роль. Сервер проверяет права независимо от UI; перед выдачей подготовленного файла и заменой данных удерживает действующие сессию, членство, владение и глобальный grant.

Создание только ручное, последние пять новых копий. Старые архивные настройки не запускают автотаймеры. Расписание и удалённое хранилище задаются только на уровне платформы.

tree-UTC-uuid.tar.gz содержит переносимую drevo.sqlite и оригиналы uploads/, связанные с людьми, снимками, источниками, историей, документами и обсуждениями этого архива. На PostgreSQL — READ ONLY REPEATABLE READ, курсор по 500 строк. Это переносимый снимок, а не рабочая БД. Не копируются чужие каталоги, previews, неиспользуемые файлы, сессии, приватные AI-диалоги, провайдерские учётные данные и ключи платформы. Каталог — tree-backups рядом с данными выбранного древа.

Оригиналы фиксируются hard link перед TAR; исчезнувший обязательный файл отменяет копию. Загрузки после публикации должны оставаться неизменяемыми. Свободный диск проверяется до записи; portable PG проверяет резерв между порциями. Старые копии удаляются только после успешной новой. SHA-256 проверяется перед скачиванием и предпросмотром.

«Восстановить» сначала проверяет копию и показывает состав; замена требует отдельного подтверждения. Правки после preview вызывают conflict revision. Учётные записи, актуальные роли, настройки и ссылки доступа остаются текущими; комментарии — только при явном выборе. Перед заменой создаётся backups/before-import-*.sqlite. Новые файлы получают новые имена, прежние не перезаписываются. Предел portable-копии — 12 ГиБ.

Прежние full-*.tar.gz остаются в backups/ или старом SSH-хранилище. Они не удаляются автоматически и не объявляются полной платформенной копией: это portable-копии одного архива. Оператор может скачать их и загрузить через «Восстановить из файла на компьютере». Старые ключи внутри TAR требуют приватных прав хранения.

## Копия платформы

/admin → Резервные копии не выбирает архив. Только глобальный администратор, без требования членства в основном древе; исследователь не получает доступ. Сохраняется вся PostgreSQL-база: все древа, аккаунты, роли, общие настройки, сервисные данные, оригиналы фото/PDF/обсуждений/вложений AI, ключи.

platform-UTC-uuid.tar.gz содержит platform.pgdump (native custom-format), shared/ (основные uploads, archives/id/uploads, AI-файлы, архивные *.secrets.key и согласованный ai-provider-cleanup.v1.key с запасной копией), platform-manifest.json (backend, все archive IDs, primary, PG version, release ID и Git commit из immutable release.json), backup-settings.json.

В legacy SQLite-установке platform.sqlite — native-копия единственной локальной БД; это не portable-копия PostgreSQL-платформы.

Глобальные catalog/job/lease/schedule находятся в shared/platform-backups/catalog.json, запись атомарна. Несколько процессов и ops/backup.sh используют общий PostgreSQL advisory lock. Изначально наследуются прежние настройки основного архива; остальные настройки не становятся глобальными. Retention относится к текущему storage target; копии в прежних SSH-подключениях остаются доступны.

Native dump и проверка обязательных файлов используют один exported snapshot. Отсутствующий оригинал, изменившийся размер или несогласованный ключ отменяют копию. pg_restore --list не заменяет полноценное восстановление.

### Оператор и хранилище

Runtime PG остаётся NOSUPERUSER/NOBYPASSRLS. pg_dump от него или --enable-row-security не является полной копией. Без PLATFORM_BACKUP_PGUSER создание отвечает 503, расписание не работает, UI сообщает необходимость настройки.

После review root запускает ops/postgres/setup-platform-backup.sh --apply. Он проверяет root-owned /etc/drevo.env, существующий локальный кластер и PGDATABASE; создаёт/проверяет отдельную LOGIN NOSUPERUSER BYPASSRLS роль с pg_read_all_data, read-only по умолчанию, CONNECTION LIMIT 2. Не меняет runtime/HBA/данные. Пароль без вывода, root-owned /etc/drevo-platform-backup.env 0600.

PLATFORM_BACKUP_PGUSER/PGPASSWORD/PGHOST/PGPORT — отдельные параметры оператора. TCP 127.0.0.1/SCRAM используется оператором; runtime остаётся на Unix socket/PEER. Второй EnvironmentFile добавляется в существующие app/backup systemd units; перезапуск в релизное окно. Нужны pg_dump/pg_restore не старше сервера, tar, свободный диск. Скрипт проверяет вход от site_drevo, выводит только readiness; секреты не передаются через argv или браузер.

Каталоги 0700; TAR/checksum/catalog/ключи 0600. Копии содержат приватные данные и действующие секреты. Для SSH: shared/backup-ssh/config, приватный ключ, закреплённый known_hosts, SFTP и Python 3.8+ на удалённом сервере. Не отключать StrictHostKeyChecking. Ошибка загрузки не удаляет прежние копии.

ops/pull-backup.ps1 скачивает platform-*.tar.gz из shared/platform-backups с проверкой SHA-256. Установленную Windows-задачу обновить отдельно. При смене storage на отдельный сервер этот pull не копирует его файлы автоматически.

**Код и инфраструктура восстанавливаются отдельно**: Git/сборка указанного commit, Node, /etc/drevo.env, operator EnvironmentFile, systemd units, nginx/TLS, SSH, OAuth/почтовые секреты. Они намеренно не включаются в скачиваемый TAR; их приватное резервирование организует оператор. Копия на том же диске не защищает от потери сервера. Внешний DR-этап не закрыт.

## Полное восстановление: offline/maintenance

HTTP не выполняет DROP/замену работающей платформы.

1. Проверить checksum TAR; безопасно распаковать в новый приватный каталог. Сверить manifest, PG version, release/commit.
2. Остановить приложение, фоновые процессы и расписание. Отдельно сохранить текущее состояние. Не восстанавливать поверх работающей БД.
3. Подготовить **новую** БД. Cluster roles отсутствуют в pg_dump: восстановить runtime/operator роли и GRANT по существующим ops/postgres setup/migration инструкциям, SECURITY DEFINER owners и ACL. --no-owner --no-acl в synthetic smoke проверяет данные, но не подготавливает production runtime.
4. pg_restore --exit-on-error в новую БД; сохранить либо осознанно переназначить владельцев. Проверить FORCE RLS и межархивную изоляцию под runtime NOSUPERUSER/NOBYPASSRLS. Использовать ops/postgres/verify-restore.sh и [инструкции PostgreSQL](postgres-migration.md).
5. Восстановить shared/ **из той же копии**, владельца сервиса и приватные права ключей, внешние конфиги и проверенный релиз. Согласованно переключить PGDATABASE/каталог. postgres.active не удалять.
6. В изоляции проверить все архивы, аккаунты, фото/PDF, обсуждения и расшифровку AI-настроек. Открыть трафик, возобновить расписание после контрольной копии.

SQLite: остановить приложение, убрать старые WAL/SHM; platform.sqlite установить под именем из manifest вместе с тем же shared/ и ключами. Замена старого drevo.sqlite на PostgreSQL ничего не восстанавливает.

RPO определяется возрастом согласованной копии и доступностью off-host storage. RTO подтверждается измеренным восстановлением; цифр пока нет. Физические pgBackRest/WAL-копии и pre-deploy snapshots сохраняют собственные runbook и не удаляются этой подсистемой.
