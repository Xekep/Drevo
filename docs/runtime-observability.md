# Наблюдаемость HTTP и ресурсов

`GET /api/admin/runtime` доступен только текущему администратору платформы;
просмотр как участник не даёт этого права. Ответ `no-store` содержит
счётчики текущего процесса: запросы, незавершённые соединения, 5xx,
429/503, отключения клиента и интервалы длительности. Также доступны
RSS/heap, суммарное CPU-время, время работы, занятые архивные runtime и
очередь их открытия, фактические total/idle/waiting/limit каждого PG pool,
занятость общего PDF-декодера.
Перезапуск обнуляет метрики. Данные людей, названия архивов, пути,
query string и токены в этот ответ не включаются.

При двух Node-процессах ответ описывает тот процесс, который обслужил запрос;
не складывайте несколько ответов как независимые временные выборки.
Для непрерывного хранения исторических метрик потребуется отдельный сборщик.
JSON-логи запросов уже содержат request ID, статус, безопасный маршрут
и длительность; Nginx остаётся источником access logs.

Workflow `Drevo availability` проверяет публичный `/api/health` каждые пять
минут, с timeout 10 секунд и двумя повторами. Health выполняет чтение версии
архива из БД. Неуспешный HTTP или `ok != true` завершает job ошибкой.
Доставка GitHub-уведомления зависит от настроек владельца репозитория;
почтовое оповещение не считается проверенным автоматически.
GitHub schedule может запаздывать: это базовая внешняя проверка, без SLA.
Для ручной проверки есть workflow_dispatch.

PostgreSQL pool по умолчанию ограничен тремя соединениями. Корневой runtime
и три открытых архива — до двенадцати соединений на Node-процесс, двадцать четыре
при двух процессах. `DREVO_PG_POOL_SIZE` принимает 3–10; увеличение требует
пересчёта бюджета с учётом `max_connections`, reserved slots, администратора,
миграционных утилит и временного пересечения старого/нового релиза.
Один слот может удерживаться advisory lock длительной задачи, второй —
транзакцией проверки прав при доставке ответа. Третий сохраняет возможность
обычных чтений и выхода из аккаунта. Два слота оказались недостаточны в
интеграционной проверке stalled ZIP delivery; проверки не ослаблены.
Waiting, 503 и рост длительности
показывают насыщение, а не необходимость автоматически повышать лимит.

PDF разбирается в дочернем процессе без окружения БД, с deadline 25 секунд
и V8 old-space 192 МБ. Это ограничение heap, не абсолютный лимит RSS.
Один корневой Node-процесс и его архивные runtime совместно используют один
активный декодер: на два Node-процесса приходится максимум два дочерних.
Закрытие runtime отменяет его задания. Общая очередь — до восьми документов;
ожидание слота ограничено пятью секундами. Перегрузка возвращает 503 и
Retry-After, готовый дисковый манифест не занимает декодер.

Производные превью очищаются каждые шесть часов при открытом архиве:
30 дней с момента создания, целевой бюджет 512 МиБ для превью и 4 МиБ для
PDF-манифестов. Публикации моложе часа защищены от удаления, поэтому
временный всплеск может превысить бюджет. Неизвестные имена и symlink
не обходятся. Оригиналы, история, staging и резервные копии этой очисткой
не затрагиваются; GC оригиналов PostgreSQL не активирован без проверки
всех ссылок истории и копий.
