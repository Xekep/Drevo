# Исправления пяти замечаний аудита — 9 октября 2026

Исходные замечания и ограничения проверки сохранены в
[полном аудите](audit-2026-10-09.md). Этот документ описывает изменения кода;
публикация в рабочем релизе проверяется отдельно. Реальные семейные данные,
настройки сервера и резервных копий для исправлений не использовались.

## A01 — соединения фоновых задач PostgreSQL

`src/server/store-database.ts` разделяет контекст короткой транзакции и
долгоживущей задачи. SQL, вложенные advisory locks и короткие транзакции задачи
используют одно её соединение. Очередь операций не позволяет параллельному
запросу случайно попасть внутрь чужой транзакции на этом соединении.

Число независимых фоновых владельцев ограничено `pool.max - 1` для каждого
пула. Ожидающие задачи не занимают соединений; ожидание ограничено пятью
секундами. При стандартном пуле из трёх соединений два фоновых владельца
оставляют третье обычным запросам. Размер пула не увеличен.

После завершения callback его контекст недействителен. Ошибка работы освобождает
блокировку; ошибка разблокировки выводит соединение из пула. Защита разных
backend-процессов по-прежнему основана на PostgreSQL advisory locks.

Проверки: `tests/postgres-task-session.test.ts`, сценарий реального PostgreSQL
в `tests/integration/postgres-runtime.ts`,
[диагностический пример](benchmarks/audit-20261009/pool-probe.mjs).
Локальный пример с синтетическим ограниченным пулом завершает все три задачи
и обычное чтение без таймаута. Это проверка механизма, а не нагрузочный benchmark
рабочей базы. Резерв одного соединения не гарантирует заданную задержку при
произвольной нагрузке обычных HTTP-запросов.

## A02 — повреждённые ссылки ИИ

`domain/research-answer.ts::researchInternalLink` безопасно разбирает внутреннюю
ссылку: декодирование выполняется один раз, повреждённое percent-кодирование,
недопустимые символы и чрезмерная длина отклоняются. В
`components/research/markdown-answer.tsx` такой текст остаётся читаемым без
нерабочей кнопки. Граница ошибки отдельного ответа изолирует прочие исключения
Markdown от всего приложения; аварийный текст выводится средствами React.

Проверки покрывают валидные ссылки, повреждённый UTF-8, повторное кодирование,
недопустимые ID, потоковый ответ и сохранённую историю на desktop/mobile.
Переход по соседней исправной ссылке остаётся рабочим.

## A03 — фокус раскрытого графа

`components/charts/research-visual-chart.tsx` использует модальный `<dialog>`.
При открытии фокус получает кнопка закрытия; Tab и Shift+Tab циклически обходят
видимые элементы окна. Фоновый чат недоступен для фокуса. Escape закрывает
окно, после закрытия фокус возвращается кнопке раскрытия.

Исходный граф и кнопка остаются смонтированными под `hidden`, поэтому закрытие
не пересоздаёт встроенный граф. Закрытый native dialog скрыт независимо от
fullscreen CSS. Проверка lifecycle добавлена в `tests/e2e/research-graph.spec.ts`.
Проверка настоящим screen reader на физическом устройстве остаётся отдельной.

## A05 — подробности архива по запросу

`data/archive-details.ts` владеет состоянием догрузки, ревизией и очередью.
Начальное открытие древа получает только `projection=overview`. Открытие
профиля запрашивает `projection=details` для конкретных людей: максимум 40 ID
и 40 фотографий на страницу. Альбом этого человека загружается без всех
фотографий остальных людей; повторное открытие использует уже прочитанные
сведения. При догрузке геометрические поля лёгкого графа сохраняются.

HTTP-обработчик в `server/archive-query-http.ts` проверяет ID, token ревизии,
членство и область чтения, фильтрует фотографии и скрытые отметки. Перед
отправкой ответа повторно проверяется доступ. Чтение использует ограниченные
SQL-запросы вместо `archive.read()`.

Коллекции загружаются только по потребности раздела: галерее нужны фотографии,
хронологии — подробные события людей, сводке и местам — обе коллекции. Страницы
ограничены 40 записями и четырьмя параллельными запросами. Редактирование
профиля доступно после загрузки его сведений. Экспорт сначала получает нужные
подробности и использует актуальный снимок.

Один конфликт чтения обновляет только overview и повторяет запрос. Повторный
конфликт завершается ошибкой; перехода на полный снимок нет. Утрата доступа
закрывает приватное представление. После обновления ревизии открытые карточки
повторно догружаются. Запоздавшие ответы подробностей и overview не откатывают
уже завершённое сохранение. Догрузка не возвращает старые настройки вида и
аватарку из начального ответа.

Проверки: `tests/archive-details.test.ts`, `tests/archive-details-http.test.ts`,
`tests/e2e/tree-details-hydration.spec.ts`, `tests/e2e/archive-edit.spec.ts`.
Синтетический архив из 10 000 людей не запускает запросы подробностей при
создании загрузчика; открытие одной карточки запрашивает только её ID.

**Оставшиеся ограничения:** полный обзор по-прежнему передаёт лёгкий граф всех
доступных людей. Хронология и аналитика после явного открытия читают всю нужную
коллекцию. Серверная проверка записи, история и полный снимок после конфликта
записи ещё работают с архивом целиком. Эти расходы не устранены данным этапом;
готовность к миллионам карточек не заявляется.

## A06 — холодная раскладка

`domain/incremental-route-score.ts` сохраняет один неизменяемый пространственный
индекс внутри конкретного расчёта. При локальном перемещении оцениваются только
изменившиеся сегменты и их контакты с остальными. Учитываются кратность общих
участков, касания, T-пересечения, длина и повороты. Для небольших графов и
масштабных изменений выполняется полная оценка.

Выбор кандидата и геометрические ограничения не ослаблены. Новый scorer
сверяется с независимой полной реализацией в
`tests/incremental-route-score.test.ts`: последовательные перемещения,
добавление и удаление рёбер, общие участки и изменение групп.

Измерено на Node 22.14 / Windows, `randomFamily(5,9)`, 977 людей: три пары свежих
процессов, без одновременно запущенных сборки или тестов. База сравнения —
`ce529f6`, а не запуск из исходного аудита на другом состоянии компьютера.

| Показатель, медиана | До | После | Изменение |
| --- | ---: | ---: | ---: |
| Полная холодная раскладка | 5 258 мс | 4 433 мс | −15,7% |
| Работа вне ELK | 2 161 мс | 1 338 мс | −38,1% |
| Вызовы ELK | 4 | 4 | без изменений |

Во всех шести прогонах совпал SHA-256 полного результата геометрии:
`1026d591cba21d38edc0a4cfbff3170edbfe2f3809366f80ec9875ddd8637e0a`.
Пропущенных людей, наложений карточек и попаданий основных маршрутов в
карточки нет. Существующие пересечения синтетического графа остались прежними;
этот этап ускоряет оценку, а не меняет критерии раскладки.
