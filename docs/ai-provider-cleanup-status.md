# Состояние очистки диалогов ИИ

В разделе «Платформа → Yandex AI» доступен раскрываемый блок «Очистка диалогов у провайдера». Он загружает очередь при открытии, показывает общие счётчики платформы и выдаёт по 20 незавершённых заданий. Фильтры — все незавершённые либо задания, требующие действий. Обновление возвращает к первой странице. Это операционная информация для администратора платформы; владелец или администратор отдельного древа её не получает.

`GET /api/admin/ai/cleanup` возвращает только локальный ID задания, состояние, число попыток, время обновления и следующей проверки, безопасную категорию ошибки и допустимый HTTP-код. Ответ не содержит удалённые ID, архивы, пользователей, диалоги, исходные credentials, ciphertext, токены lease или произвольный текст ошибки провайдера. `Cache-Control: no-store`; курсор привязан к фильтру и проверяется до SQL. Постраничный запрос ограничен 21 строкой, включая признак следующей страницы, и использует индекс порядка `(updated_at, id)` без OFFSET. Временная смена состояния или времени задания может изменить состав следующих страниц; кнопка обновления начинает новый просмотр текущей очереди.

В PostgreSQL перед выдачей заново проверяются сеанс, одобренное членство и системный допуск. Строки прав удерживаются до ограниченного по времени завершения записи HTTP-ответа; одновременно изменяющиеся права дают конфликт, отозванные — отказ без очереди. SQL ограничен двумя секундами, передача ответа — четырьмя. Счётчики считаются для всех незавершённых заданий одним снимком с текущей страницей; при росте очереди их расчёт требует чтения большего числа записей. В SQLite явно показывается отсутствие долговечной очереди.

Интерфейс только читает состояние и не запускает DELETE у провайдера. Временные ошибки повторяет существующий worker. Заблокированные задания пока нельзя возобновить кнопкой: контролируемый повтор с неизменным исходным подключением остаётся отдельным этапом. Новый API-ключ в настройках не меняет зашифрованное подключение ранее зарегистрированных заданий. Повреждённый snapshot требует проверки соответствующих ключа и системного восстановления; ручную замену credentials в таблице этот интерфейс не предлагает.

Успешное удаление Conversation у Yandex не доказывает удаления его элементов. Поэтому список не выдаёт такую гарантию. Прежние ID без достоверного исходного подключения и окно падения до долговечной регистрации ID сохраняют ограничения [основного контракта](ai-provider-cleanup.md).

Проверки: HTTP на отдельной PostgreSQL БД с настоящим архивным пулом, безопасная проекция ошибок, пагинация при одинаковых timestamps, оба индексных плана без общей сортировки, владелец древа без системного допуска, отзыв допуска и сеанса после начальной аутентификации; SQLite-ограничения; браузерные desktop/mobile проверки открытия, фильтра, страниц и переполнения. Реальный провайдер и рабочие диалоги в этих тестах не используются. Полный Linux PostgreSQL-профиль проходит через CI; локальный Windows-профиль после нового успешного сценария останавливается на прежней проверке файловых symlink.
