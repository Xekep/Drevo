# Документы

Загрузки PDF ограничены 20 МБ на файл, общей с фотографиями квотой 10 ГиБ/20 000 файлов на архив, 60 попытками в час на участника и 16 одновременными PDF-загрузками. Перед началом сервер резервирует максимальный объём в SQLite и оставляет минимум 256 МиБ свободного места на диске. Загрузка ограничена двумя минутами, после завершения повторно проверяются права. Квота/нехватка места возвращает `507`, ограничение частоты — `429`. Загрузки фотографий тоже учитывают уже сохранённые PDF и их незавершённые резервы.

Раздел `/documents` хранит PDF, загруженные участниками архива. Это отдельные файлы: временные PDF-отчёты ИИ и ссылки из текстовых источников сюда не попадают.

Участник с правом редактирования указывает название и связывает документ с одним или несколькими людьми, которых он видит. Файл до 20 МБ передаётся потоком, хранится в каталоге `uploads/` под случайным именем. SQLite хранит метаданные в `documents`, привязки — в `document_people`. Список загружается страницами по 30 записей; документ показывается в группе каждого связанного человека. После удаления карточки связь удаляется, а документ остаётся в группе «Без привязки» для участников с полным доступом.

`GET /api/documents?offset=0&limit=30` возвращает `{total,items}`. `POST /api/documents` принимает `Content-Type: application/pdf`, бинарное тело и URL-кодированный JSON `{title,personIds}` в `X-Document-Metadata`. `GET /api/documents/<id>/file` отдаёт PDF только участнику, которому доступен хотя бы один связанный человек. Для участников с ограниченным деревом список и выдача файла проверяют видимую ветвь на сервере. Публичный доступ к дереву или фото сам по себе не открывает документы.

Полный бэкап включает SQLite и каталог `uploads/`, включая PDF. Предпросмотр восстановления проверяет наличие и сигнатуру файлов; применение восстанавливает их вместе с метаданными в одной транзакции архива. Очистка сиротских файлов учитывает документы, а также ссылки в сохранённых SQLite-бэкапах.

Ридер использует PDF.js для отрисовки страниц и StPageFlip для перелистывания. Сначала рисуется только первая страница, остальные подгружаются по мере чтения. Поддерживаются документы до 2000 страниц; исходный PDF можно открыть отдельно. На узком экране страницы идут по одной.

Сразу после загрузки открывается книга в режиме выделения. Участник с правом редактирования проводит по фрагменту страницы и добавляет комментарий. Координаты хранятся как доли ширины и высоты страницы, поэтому выделение остаётся на месте при смене размера окна. Справа находится список комментариев; при выборе записи книга быстро перелистывает страницы к нужной и подсвечивает фрагмент. На узком экране список находится под книгой. Комментарии видны только тем, кому доступен сам документ. Удалить запись может её автор или администратор. Комментарии сохраняются в `documents.annotations` и входят в полный и переносимый бэкап.

`GET /api/documents/<id>/annotations` возвращает список. `POST` принимает JSON `{page,x,y,width,height,text}` с нормализованными координатами; `DELETE /api/documents/<id>/annotations/<annotation-id>` удаляет запись с проверкой автора. Сервер проверяет доступ к документу при каждом запросе и повторно внутри транзакции записи.

Параметр `q` в `GET /api/documents` фильтрует весь каталог по названию документа или ФИО связанного человека до применения `offset` и `limit`.
