# Документы

Загрузки PDF ограничены 20 МБ на файл, общей с фотографиями квотой 10 ГиБ/20 000 файлов на архив, 60 попытками в час на участника и 16 одновременными PDF-загрузками. Перед началом сервер резервирует максимальный объём в базе и оставляет минимум 256 МиБ свободного места на диске. Загрузка ограничена двумя минутами, после завершения повторно проверяются права. Квота/нехватка места возвращает `507`, ограничение частоты — `429`. Загрузки фотографий тоже учитывают уже сохранённые PDF и их незавершённые резервы.

Раздел `/documents` хранит PDF, загруженные участниками архива. Это отдельные файлы: временные PDF-отчёты ИИ и ссылки из текстовых источников сюда не попадают.

При загрузке доступны необязательные сведения: тип, дата или период, место, описание и происхождение документа. Историческую дату можно записать текстом, например «1887 год»; она не становится датой события в древе. Эти сведения доступны в ридере и поиске по каталогу, сохраняются в полной и переносимой копиях, офлайн-архиве и в собственном расширении Drevo форматов GEDCOM/GEDZIP. Сторонние программы могут игнорировать это расширение.

Участник с правом редактирования указывает название и может связать документ с одним или несколькими людьми, которых он видит. При доступе ко всему архиву PDF можно загрузить и без привязки; при ограниченном доступе требуется хотя бы один видимый человек. Файл до 20 МБ передаётся потоком, хранится в каталоге `uploads/` под случайным именем. База хранит метаданные в `documents`, привязки — в `document_people`. Список загружается страницами по 30 записей; документ показывается в группе каждого связанного человека либо в группе «Без привязки». После удаления карточки связь удаляется, а документ остаётся в группе «Без привязки» для участников с полным доступом.

`GET /api/documents?offset=0&limit=30` возвращает `{total,items}`. `POST /api/documents` принимает `Content-Type: application/pdf`, бинарное тело и JSON `{title,personIds,documentType,documentDate,place,description,provenance}` в `X-Document-Metadata` с префиксом `base64:`; прежний URL-кодированный JSON также принимается. Дополнительные поля необязательны, `personIds` может быть пустым только при доступе ко всему архиву. `GET /api/documents/<id>/file` отдаёт PDF участнику с доступом ко всему архиву либо к одному из связанных людей. Для участников с ограниченным деревом список и выдача файла проверяют видимую ветвь на сервере. Публичный доступ к дереву или фото сам по себе не открывает документы.

Автор документа или администратор может изменить название и дополнительные сведения без повторной загрузки PDF. `PATCH /api/documents/<id>` принимает JSON `{expected,next}`, где оба объекта содержат название и дополнительные поля. Сервер сравнивает `expected` с текущей записью внутри транзакции и возвращает `409`, если другой участник успел изменить документ; права, видимую область и источник запроса он проверяет повторно перед записью. Связанные люди и сам файл этим запросом не меняются.

Полный бэкап должен включать базу и каталог `uploads/`, включая PDF. PostgreSQL резервируется нативным дампом и локальным PITR, SQLite — файлом базы; копию файлов нужно сохранять согласованно с данными. Переносимый архив содержит документы и позволяет восстановить их вместе с метаданными. Очистка сиротских файлов учитывает документы и ссылки в сохранённых переносимых копиях.

Ридер использует PDF.js для отрисовки страниц и StPageFlip для перелистывания. Сначала рисуется только первая страница, остальные подгружаются по мере чтения. Поддерживаются документы до 2000 страниц; исходный PDF можно открыть отдельно. На узком экране страницы идут по одной.

Сразу после загрузки открывается книга в режиме выделения. Участник с правом редактирования проводит по фрагменту страницы и добавляет комментарий. Координаты хранятся как доли ширины и высоты страницы, поэтому выделение остаётся на месте при смене размера окна. Справа находится список комментариев; при выборе записи книга быстро перелистывает страницы к нужной и подсвечивает фрагмент. На узком экране список находится под книгой. Комментарии видны только тем, кому доступен сам документ. Удалить запись может её автор или администратор. Комментарии сохраняются в `documents.annotations` и входят в полный и переносимый бэкап.

`GET /api/documents/<id>/annotations` возвращает список. `POST` принимает JSON `{page,x,y,width,height,text}` с нормализованными координатами; `DELETE /api/documents/<id>/annotations/<annotation-id>` удаляет запись с проверкой автора. Сервер проверяет доступ к документу при каждом запросе и повторно внутри транзакции записи.

Параметр `q` в `GET /api/documents` фильтрует весь каталог по названию документа или ФИО связанного человека до применения `offset` и `limit`.
