# Приглашения в древо

Новые одноразовые ссылки имеют вид `/join/<токен>`. Идентификатор архива не
попадает в адрес, который пользователь копирует в переписку. Это уменьшает
раскрытие внутренних идентификаторов; сам токен остаётся секретом доступа.
Он содержит 32 случайных байта, в БД хранится только SHA-256.

Клиент передаёт токен в JSON-теле POST `/api/account/invitations/preview` или
`/api/account/invitations/accept`, не в query-параметрах. Служебный `archiveId`
возвращается сервером для перехода в выбранное древо после принятия.

В PostgreSQL миграция 101 добавляет только SELECT-политику
`invitation_token_lookup` к `archive_invitations`. Внутри одной транзакции
сервер устанавливает `drevo.invitation_token_hash`, находит ровно одну
действующую запись по существующему глобальному UNIQUE(token_hash) и сразу
очищает эту capability. Политика не открывает людей, членство или изменения
в чужом архиве. Затем выполняется прежний путь под обычным target archive RLS:
блокировка архива, проверка сеанса, блокировка приглашения, проверка срока,
отзыва, привязки человека и атомарное добавление участника.

Повторное принятие тем же аккаунтом идемпотентно. Другой аккаунт не может
принять использованный токен; конкурентные запросы расходуют его один раз.
Предпросмотр использованной ссылки закрыт. Блокировки предпросмотра удерживаются
до окончания короткой HTTP-выдачи, поэтому завершённый отзыв не раскрывает
название и роль. Проверки Origin, размера тела, типа JSON и активного сеанса
не меняются. Ссылки обслуживаются с no-store/no-referrer/noindex;
application access log заменяет любой `/join/...` на `/join/[redacted]`.

Временная совместимость: старые `/join/<archiveId>/<токен>` и прежние JSON-тела
с archiveId продолжают работать без перевыпуска приглашения. Неверный архив
в старой ссылке не перенаправляется в найденный по токену. Удаление fallback
запланировано в [R7.1 дорожной карты](roadmap.md): после истечения последнего
токена, выданного старым релизом (максимум 720 часов с последней выдачи).
Не удалять этот путь только по дате выкладки нового клиента.

Регрессии: `archive-routes.test.ts`, `production-static-http.test.ts`,
`safe-request-route.test.ts`, `e2e/archive-invitations.spec.ts` и native
`integration/postgres-opaque-invitations.ts`; существующие проверки отзыва
сеанса и завершённой выдачи предпросмотра используют token-only JSON.
