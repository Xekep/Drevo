# Открытие древ и кеши backend

## Ограниченный запуск

`archiveRoutePool` открывает до четырёх разных древ параллельно. Повторные
запросы одного древа разделяют одно открытие, но каждый независимо проверяет
доступ после ожидания. Отзыв доступа первого посетителя не подменяет права
другого ожидающего посетителя. Запуск не публикуется, если доступ потеряли все.

Очередь ограничена 256 открытиями и 30 секундами ожидания; исчерпание даёт
503 с `Retry-After`. Бюджет 128 runtime включает открываемые и закрываемые
экземпляры. Активные обработчики, включая продолжающийся ответ ИИ после
разрыва SSE, не вытесняются. Останов сервера закрывает очередь и дожидается
открываемых/закрываемых ресурсов. Отдельные startup-слоты не являются SQL-пулом.

Общий PostgreSQL-пул владеет координатором глобальных проверок схемы. Они
объединяются и выполняются один раз после успешной проверки на этом пуле;
ошибка допускает последующий повтор. Архивные backfill членства, публикаций,
ссылок на документы и staged import выполняются для каждого открываемого древа
под прежним RLS. Standalone-пулы остаются независимыми.

## Общий бюджет кешей

Снимки, поисковые индексы, граф проверки видимости и множества доступных ID
конкурируют за один LRU-бюджет на процесс. `archiveCacheView` связывает ключи
с runtime: закрытие древа освобождает его производные структуры, не очищая
соседние древа. Callback вытеснения удаляет и служебные карты ключей.

Размеры строк считаются в UTF-16, размеры производных объектов учитываются
консервативной оценкой их полей и служебных структур. Этот бюджет ограничивает
удерживаемые кеши, **не является ограничением RSS** и не учитывает одновременно
подготавливаемые ответы. Вытеснённые индексы не удерживаются второй ссылкой
в замыкании владельца. Несколько одинаковых загрузок разделяют pending-результат.

Граф видимости содержит ID, авторство, родительские и супружеские связи,
участников союзов. Фотографии, портреты, биографии, события и описания источников
для определения доступных людей не читаются. Разные HTTP-обработчики одного
древа используют один владелец графа и областей доступа.

## Транзакции и права

Ключи учитывают ревизию древа и актуальные поля доступа пользователя. Ревизия
читается SQL-запросом в контексте текущей транзакции, без COUNT людей и фото.
Результат загрузки другого SQL-снимка принимается только при совпадении ревизии.

`canReuseGraphCache()` разрешает кеш вне транзакции, в транзакции чтения либо
в явно объявленной `graphReadOnly`-транзакции с общей блокировкой архива.
Последний вариант предназначен для квитанций уведомлений: они меняют квитанции,
но не семейный граф. Произвольная запись всегда обходит кеш и не публикует
свои изменения в общий индекс; rollback не должен оставлять несохранённые ID
или имена для других посетителей. Нельзя объявлять `graphReadOnly` обработчик,
который меняет людей, отношения, союзы или ревизию.

Кеш не заменяет авторизацию. Проверки сеанса, членства, отзыва доступа,
соответствия ревизии и защищённой выдачи ответа остаются в HTTP-обработчиках.
