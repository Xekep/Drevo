# Общие настройки платформы

Панель платформы `/admin` и управление древом `/manage` используют одну
визуальную систему: боковая навигация на компьютере, горизонтальная полоса
разделов на телефоне, компактные заголовки и формы. `AdminNavigation` отвечает
за видимость выбранного пункта после смены ширины. Это общий компонент
навигации, а не общий набор разрешений: фильтрация разделов и API-проверки
остаются в соответствующих владельцах панелей.

В `/admin` раздел «Пользователи» объединяет глобальную роль и уровень доступа
в одной строке. Поиск по имени или ID не различает регистр и е/ё; `%` и `_`
рассматриваются как обычные символы. Через 250 мс после ввода запрос заменяет
страницу списка без перезагрузки; поздний ответ старого поиска игнорируется.
`GET /api/platform/accounts?q=…&after=…` возвращает до 30 аккаунтов и курсор
следующей страницы. Сортировка — `lower(name), id` с `COLLATE "C"`; отдельный
индекс и keyset-пагинация обходятся без OFFSET. Поиск по вхождению остаётся
линейным по числу аккаунтов; индекс не превращает его в полнотекстовый поиск.
Страницы не запрашивают общее количество аккаунтов. Кнопка «Статистика» открывает
отдельное окно с `GET /api/platform/accounts/statistics`; расход конкретного
владельца открывается значком в его строке через прежний endpoint квот.
API проверяет действующий глобальный допуск под блокировками перед запросом
и перед отправкой, с ограничением времени выдачи. Изменения роли и уровня
используют прежние проверенные PATCH-контракты; это независимые разрешения.
При конфликте квоты список читает актуальное значение, сохраняя сообщение об ошибке.

Таблица участников использует CSS container queries. При доступной ширине
до 780 px строки становятся блоками с явными подписями полей; до 340 px
область доступа занимает всю строку, чтобы «Кровные родственники» оставались
читаемыми. Подсказка о ролях раскрывается по нажатию. Размеры мобильных
элементов управления сохранены, личный кабинет не получает стили уплотнения.

В «Участниках» первое нажатие удаления только запрашивает подтверждение;
второе закрывает доступ к выбранному древу. Esc, уход фокуса и восемь секунд
ожидания отменяют подтверждение. PostgreSQL удаляет только членство и личный
вид этого архива: аккаунт, сеансы, данные людей и доступ к другим древам остаются.
Владельца нельзя удалить до передачи владения.

Приглашение задаёт роль в древе — читатель или родственник. При выбранном
человеке можно открыть всё древо либо кровных родственников, их партнёров
и непосредственных вторых родителей кровных потомков, даже без брака;
без привязки область всегда «Всё древо». Выбранная область не повышает роль.
Сервер проверяет человека в том же архиве при выпуске и принятии, а пропавшая
или уже занятая привязка не расширяет область автоматически. Приглашение
не заменяет другую привязку аккаунта и не расширяет уже одобренный доступ.
Старые ссылки сохраняют область «Всё древо» без привязки. Неиспользованную
ссылку с удалённым человеком нужно отозвать и выпустить заново.

В Yandex AI сначала показано подключение, затем доступ по ролям и расход с
общим бюджетом. Настроенное подключение, общие настройки и контекст раскрываются
отдельно. Для роли с наследованием видна короткая сводка возможностей вместо
неактивной формы; отключение наследования создаёт отдельный профиль.
Администратор и исследователь — роли платформы; родственник и читатель — роли
в древе. Политика ИИ не повышает права на данные, а читателю по-прежнему
запрещены предложения изменений.

Общий поиск в интернете задаёт значение по умолчанию, которое можно изменить
в профиле роли. Общий переключатель Python разрешает возможность для всех ролей:
если он выключен, отдельный профиль её не включит. Личные дневные лимиты
задаются только в отдельном профиле; общий бюджет древа ограничивает суммарный
расход всех пользователей, в том числе при наследовании.

Переход между ролями сохраняет черновики; общая кнопка «Сохранить» применяет их
вместе. Форма показывает наличие изменений и предупреждает при смене раздела,
древа, уходе в профиль или закрытии страницы. На время проверки или сохранения
редактирование блокируется. «Проверить подключение» и «Проверить модель роли»
отправляют текущий черновик в `POST /api/admin/ai/test`: сервер валидирует его
так же, как сохранение, и проверяет без записи настроек или ключа в БД.
Проверка требует действующего права администратора платформы и повторно
проверяет его после ответа провайдера. Старый запрос без тела проверяет
сохранённое подключение. API-ключ не возвращается в ответах и не сохраняется
в хранилище браузера. Очередь очистки данных у провайдера находится внизу раздела.

Кнопка меню остаётся справа и в админке, где нет поиска по древу. Переключение
разделов не перемонтирует аватарку. На страницах без семейного графа
`GET /api/account/portrait` читает только фотографию привязанной карточки
текущего одобренного участника выбранного архива. Идентификатор другого человека
задать нельзя; публичный просмотр и режим просмотра глазами участника этот
эндпоинт не открывают. Перед выдачей сервер перепроверяет доступ и версию архива.
Портрет не сохраняется в локальное хранилище браузера; при отсутствии привязки
или недоступном изображении меню показывает инициал аккаунта.

В PostgreSQL лимиты загрузок, подключение VK ID и справочник ресурсов поиска едины для всех древ. Их меняет только администратор платформы с действующим сеансом. Владелец древа без этого права не получает доступ к настройкам, даже если он управляет участниками и данными своего древа. Публичный просмотр справочника ресурсов доступен читателю древа; право на изменение справочника из этого не следует.

При первом запуске после обновления основной архив, указанный через `ARCHIVE_ID`, переносит свои действующие лимиты, настройки VK ID, категории и ресурсы в общие таблицы. Сохраняются идентификаторы, порядок, настройки поиска ИИ и собственные ресурсы основного архива. Если его справочник пуст, используется стартовый список. Повторный запуск не перезаписывает уже общие настройки. Сервер выбранного архива не выполняет первичный перенос.

Старые записи других архивов остаются в их таблицах для отдельной операторской инвентаризации и ручного переноса, но не становятся частью общего справочника автоматически. Приложение не публикует объединённый список приватных ссылок. Перед ручным переносом оператор должен проверить право на публикацию каждой записи и её URL, включая параметры запроса. Самостоятельного интерфейса инвентаризации и переноса в этом этапе нет.

Общие настройки входят в системную резервную копию PostgreSQL. Переносимый архив отдельного древа и его прежние локальные строки больше не являются резервной копией действующих общих настроек. При восстановлении всей платформы нужно восстанавливать системную БД, а не полагаться на архивный TAR отдельного древа.

Общий лимит загрузок применяется по текущей глобальной роли и роли читателя в древе; локальная роль читателя не повышается глобальным назначением. Отдельная квота базового аккаунта владельца (500 МБ и 150 человек) продолжает действовать независимо от общего лимита. Локальный SQLite-режим сохраняет прежние настройки одного древа.

В `/admin` резервируется вся платформа: нативная база PostgreSQL всех древ, общие настройки, оригиналы и ключи. Выбор отдельного архива не нужен; доступ проверяется по глобальной роли администратора и действующему сеансу, без требования членства в древе. Период, количество копий и локальное или внешнее хранилище относятся только к этому разделу.

В `/manage` доступны ручные копии выбранного древа: последние пять, без расписания и глобальных секретов. Раздел виден одобренному владельцу с глобальной ролью исследователя или администратора; сервер проверяет эти права независимо от интерфейса. Просмотр глазами участника не позволяет создавать, скачивать или восстанавливать копии. Восстановление древа использует предпросмотр и проверку версии; полное восстановление платформы выполняет оператор в режиме обслуживания. См. [бэкапы](backup.md).
